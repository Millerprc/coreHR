# ADR-0005 Pencil 原型先行门禁与画板登记

> 状态：Accepted
> 日期：2026-10-24
> 决策人：Miller、Mavis
> 关联任务：D-068 / D-087 / D-090 / D-091；本轮 `.pen` 原型落地与前端对齐

## 背景

`coreHR` 的前端长期存在「界面按实现走、产品没看过原样」的断层：页面由开发侧直接实现，评审发生在代码之后，导致 Ant Design 载体规范（DRAWER / MODAL / NEW_TAB）只在文档里存在、实际界面不统一，字段口径也缺少产品签字的单一事实源。

2026-10-24 用户在检查 `coreHR.pen` 时提出「前端的所有页面可能有问题」，并要求把已有需求先做产品页面设计、落到 `.pen` 文件，再让前端按画板开发或替换已有界面。这把「原型先行」从惯例变成了必须执行的门禁。

同时，《Ant Design 页面与交互载体规范》（`docs/design/antd-page-interaction-standard.md` v1.1，ACTIVE）§10.2 已经规定：Pencil 原型未达到 `PROTOTYPE_APPROVED` 之前不得创建对应的前端开发任务。但此前既没有画板，也没有承载该状态的文档，门禁无从执行。

## 决策

- **原型先行**：任何新增或替换的产品页面，必须先在 `C:\Users\83289\Documents\HRMS\coreHR.pen` 中存在对应画板，前端实现以画板为视觉与结构基准，不得自由发挥。
- **画板必须忠实反映实现，不得理想化**：画板中的字段、文案、列序必须逐条对齐现有代码与后端契约；凡实现里存在但没做控件的（例如职位载荷的 `source_job_id` / `attributes`）、凡语义上不一致的（例如职位页「重置」不清生效日期而日志页「重置」清全部筛选），一律在画板与设计说明书中如实保留，不得按「理想形态」美化。
- **画板登记是门禁的技术载体**：每个功能需求文档 §10.4 必须登记「Pencil 源文件 / 画板 ID / 画板名称 / 原型版本 / Review 状态」。Review 状态从 `DRAFT_FOR_REVIEW` 改为 `PROTOTYPE_APPROVED` 须有用户签字，不允许自行升级。
- **组件层优先**：画板侧的可复用组件（`COMP` 前缀）与代码侧的公共组件层（`apps/web/src/business/components/`）一一对应；同一能力域不得出现第二套结构写法（D-091）。
- **载体选择固定为三种**：宿主页 + MODAL / DRAWER / NEW_TAB，不引入第四种承载方式。
- **字体变量固定**：`.pen` 的 `$corehr-font` 保持 `Noto Sans SC`。这是 Pencil 判定合法的字体（`Microsoft YaHei` / `Source Han Sans SC` / `PingFang SC` 均被判为 invalid），改用本地字体名会导致渲染退化。

## 备选方案

### 不做原型，直接按需求文档写前端

- 优点：快，无双份维护成本。
- 缺点：产品评审发生在实现之后；载体规范无法被检查；字段口径缺少可签字的事实源。
- 未采用原因：本轮问题正源于此——用户第一次看到界面形态是在 `.pen` 里，而非在实现中。

### 用 Figma 承载原型

- 优点：协作生态成熟。
- 缺点：与仓库不同步、不在版本控制内；无法在本机通过工具做字段级取证；与项目既定的 Pencil 链路不一致。
- 未采用原因：项目已选定 Pencil，且本次取证与导出链路已验证可用。

### 画板按「理想形态」绘制，实现去迁就画板

- 优点：画板好看。
- 缺点：制造出后端不存在的字段，违反「不发明字段」原则；实现要为此造假或改契约。
- 未采用原因：画板必须反映真实契约，否则原型本身成为新的误导源。

## 影响

- 每个新页面多一次画板设计与一次产品评审，交付周期变长，但返工率下降。
- 画板与实现存在时间差时，以画板为准并同步更新实现，不允许实现与画板长期分叉。
- `.pen` 源文件目前位于仓库外（`C:\Users\83289\Documents\HRMS\coreHR.pen`），**不进版本控制**；需要长期追溯时应把画板 ID 与预览图登记进 `docs/review/pen-prototypes/`（已做）并把 ID 写进功能需求文档。
- 前端实现必须通过 AntD 6.5.2 废弃属性守卫（`apps/web/scripts/check-antd-usage.mjs`），画板本身不替代该守卫。

## 验证证据

- `coreHR.pen` 由 111276 B 增至 513630 B；根节点 19 个（1 个既有原型 + 12 个可复用组件 + 6 个新画板），总节点 1049，reusable 12，ref 24，文本节点 403（其中 331 个含中文）。
- 6 个画板以 2× PNG 实拍导出到 `docs/review/pen-prototypes/`，中文全部正常渲染（文件名与大小：01-职位管理 319020 B、02-汇报关系 310506 B、03-操作日志 335332 B、04-人员中心 301409 B、05-员工档案Drawer 352591 B、06-批量新增标签Modal 344844 B）。
- 文件字节校验：`json.loads` 成功，U+FFFD 替换字符 0 个，无 BOM，纯 UTF-8。
- 字体链路：`GetVariables()` 返回 `$corehr-font = Noto Sans SC`；Windows 字体枚举确认 `Noto Sans SC` 已安装（7 个字重）；6 组字体探针中仅 `Noto Sans SC` 与 `Inter` 被 Pencil 判定合法；Google Fonts CSS 336 KB / 101 个 gstatic URL，字体文件 HEAD 200、298 ms。
- 结论：**「中文未渲染」在当前环境无法复现**，定性为扩展首次打开时字体尚未加载完成的环境时序现象，而非文件缺陷，故不修改文件编码与字体变量。
- 设计说明书：`docs/review/pen-prototype-spec-2026-10-24.md`（含 8 行取证表、6 条「与现有实现的差异说明」、8 条待产品确认）。

## 复审条件

- Pencil 升级到新版本，或 `$corehr-font` 合法性规则变化。
- 引入 Figma 或其他原型工具，形成双原型源。
- 载体规范新增第四种承载方式（例如工作区标签页）。
- 产品要求把 `.pen` 纳入版本控制或建立多分支画板协同。

# ADR-0004 人员敏感字段应用层保护

> 状态：Accepted
> 日期：2026-08-12
> 决策人：项目负责人、Codex
> 关联任务：PER-002～PER-005、PER-009～PER-013

## 背景

第一阶段人员档案将保存证件号码、个人联系方式、详细地址及紧急联系人等敏感信息。仅依赖磁盘或数据库透明加密，不能阻止应用查询、导出、错误和日志泄漏；同时，系统需要在不保存可检索明文的前提下完成证件及联系方式精确去重。MVP部署规模较小，但密钥边界必须能平滑迁移到后续KMS或集中密钥托管。

## 决策

1. 敏感值在进入SQLAlchemy模型前，使用受维护密码库提供的AES-256-GCM进行应用层认证加密。每个值使用随机96位nonce；密文保存密钥版本、nonce及包含认证标签的密文，字段类别和所属记录稳定标识作为AAD。
2. 精确检索与去重使用独立256位密钥生成HMAC-SHA-256摘要；每类字段先执行明确的规范化和域分离。摘要密钥与加密密钥不得复用，普通SHA摘要不得用于证件或联系方式。
3. 普通列表、详情、搜索、导出、错误和审计默认只包含脱敏值。明文读取使用独立动作，要求`PERSON_SENSITIVE_REVEAL`权限和非空原因，并记录操作者、Person、字段类别、记录ID、时间和Trace ID；审计不保存明文。
4. MVP从运行环境注入版本化加密密钥环、当前写入版本和独立摘要密钥，禁止写入仓库、数据库、镜像和日志。缺失密钥、未知版本、认证失败或密文篡改时，敏感操作失败关闭，不回退为空值或明文；非敏感功能可以继续运行。
5. 轮换采用“新写入使用新版本、旧版本保留解密、受控批次重加密”的方式。生产启用真实数据前，必须完成密钥备份、恢复、轮换和职责交接演练；后续可将同一密钥提供接口替换为KMS。

## 备选方案

### 仅使用磁盘或数据库透明加密

- 优点：部署简单，对业务代码影响小。
- 缺点：应用账号仍可读取明文，不能约束页面、导出、日志和越权查询。
- 未采用原因：无法满足字段级最小权限和逐次明文访问审计。

### 在PostgreSQL内使用数据库函数加解密

- 优点：加密逻辑靠近数据，应用字段较少。
- 缺点：数据库会接触密钥和明文，查询权限、密钥轮换及未来多数据库兼容更难治理。
- 未采用原因：与第五阶段可能评估MySQL/Oracle的方向冲突，也扩大数据库管理员明文访问面。

### 首版接入独立数据保险库或外部KMS

- 优点：密钥与敏感数据隔离最强，集中审计能力好。
- 缺点：增加网络依赖、部署成本、可用性设计和本机实验复杂度。
- 未采用原因：不适合作为8GB实验性MVP的前置条件；保留兼容接口，在生产化阶段复审。

## 影响

### 正面

- 数据库备份、只读查询和普通应用接口不会直接暴露受保护明文。
- 去重和精确匹配不需要可逆索引，并可保持数据库唯一约束。
- 密钥版本、脱敏、Reveal和审计形成一致的跨实体安全边界。

### 代价

- 不能对加密值进行模糊查询或排序；搜索必须使用受控摘要或非敏感字段。
- 密钥轮换、备份和灾难恢复成为正式运维职责；密钥丢失无法通过重置密钥恢复历史数据。
- 每个敏感实体都必须显式保存加密封装和脱敏投影，禁止把任意敏感值塞入JSON。

### 风险与缓解

- AAD字段变化会导致历史密文无法解密：AAD只使用稳定实体类型、记录ID和字段代码，不使用可修改显示值。
- 低熵字段摘要可能被离线枚举：摘要使用独立秘密HMAC密钥并限制数据库及密钥同时访问；不为无需精确检索的字段生成摘要。
- 明文可能在异常或通用审计中泄漏：敏感服务返回受控值对象，通用审计只接收脱敏摘要；测试扫描日志、错误响应和序列化结果。

## 验证证据

实现完成前必须通过：随机nonce、篡改拒绝、错误密钥版本、规范化摘要稳定、默认脱敏、Reveal权限与原因、审计无明文、日志无明文、轮换兼容及数据库无明文扫描测试。

## 复审条件

- 生产环境启用真实人员敏感数据。
- 引入外部KMS、HSM、独立数据保险库或多租户密钥隔离。
- 第五阶段正式支持MySQL或Oracle。
- 法规、数据驻留或企业安全制度要求更换算法、密钥周期或访问审批方式。

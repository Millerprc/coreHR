# 第一阶段人员档案实施 Review

> Review基线：2026-08-12 `main`分支本机代码
>
> 适用对象：项目负责人、HR系统主管理员
>
> 数据边界：本轮只使用结构与合成数据，没有上传、复制或提交企业真实人员数据

## 1. 结论

本轮人员档案已达到**主管理员工程UAT可开始**状态，但还不能声明“企业真实人员数据迁移完成”或“生产替换完成”。

核心建档、四类法人主体有效期、敏感子档案、加密脱敏、受控明文查看、内容/有效期更正、失效、审计、待入职主证件闸门及Person非敏感基础层导入导出已经形成闭环。敏感批量迁移、正式企业表头、细分角色字段遮罩和容量验证仍需后续专项完成。人员子档案不提供物理删除，错误数据通过有因更正或失效保留历史。

## 3. 已实现功能清单

### 3.1 人员基础档案

- 创建和更正Person；法定姓名必填，展示姓名自动默认。
- 保存已确认的自然人基础字段，更正审计只记录变更字段，不记录敏感前后值。
- 六位工号、二次入职沿用原Person/工号等既有规则不变。

### 3.2 法人主体关系

- 合同、发薪、社保、个税主体使用四种独立关系类型。
- 同一类型按生效日期版本化；新增未来版本自动闭合前一版本。
- 可按任意查看日期取得结果，并单独查看完整历史。

### 3.3 敏感及关联子档案

- 证件、联系方式、地址、紧急联系人。
- 教育经历、工作经历、家庭成员。
- 普通响应只返回脱敏投影；明文通过独立Reveal动作读取。
- Reveal要求权限和原因，并审计操作人、Person、字段、记录、时间和Trace ID；不审计明文。
- 页面只在临时弹窗展示明文，关闭后清除前端状态。
- 七类子档案均支持有因内容更正、有效期更正和失效；不提供物理删除。
- 更正敏感值时必须重新输入新值，页面不会先读取并回填现有明文。
- 创建待入职劳动关系前，计划入职日必须存在已核验且有效的主要证件。
- 新人录用可在同一事务中加密创建主要证件；复聘默认沿用原人员档案和原工号，可选择重新录入新证件。

### 3.4 分层初始化

- `person_basic`模板、预校验、执行、来源追踪和当前CSV导出已开放。
- 当前模板只允许`employee_number`、`legal_name`、`display_name`、`former_name`。
- 未知列和敏感列会被拒绝，防止明文进入通用导入行JSON。

## 5. 明确未完成与风险

1. **不得导入真实敏感数据。** 当前没有敏感批量导入的加密暂存和对账链路；只能使用页面/API单笔加密建档或合成数据测试。
2. **基础敏感字段仍按字段权限控制。** 出生日期、性别、国籍等保存在Person结构化列中，由`PERSON_SENSITIVE_VIEW`控制；当前没有逐字段Reveal弹窗。若未来开放非主管理员角色，需要再细分默认遮罩策略。
3. **子档案不提供物理删除。** 这是有意的审计边界；录错内容走有因更正，不再有效的记录走失效，原操作和历史均保留。
4. **教育、工作和家庭字段为最小通用集。** 收到企业正式表头后需做增量字段迁移，不能把未知字段塞入JSON。
5. **生产密钥未写入仓库或Compose。** 这是有意的安全边界；人工UAT前需按密钥运行手册在本机进程注入测试密钥，并妥善保存同一组测试密钥。
6. **未执行真实数据迁移和万人容量测试。** 本轮通过仅代表工程功能和安全契约，不代表生产规模。

## 6. 建议Review时间

本次人员档案增量建议预留**90分钟完整Review**；只检查核心安全主链可压缩为**45分钟**。

| 环节 | 完整Review | 核心Review |
|---|---:|---:|
| 字段合同和边界 | 15分钟 | 5分钟 |
| Person与四类主体 | 20分钟 | 10分钟 |
| 敏感子档案、脱敏和Reveal | 25分钟 | 15分钟 |
| 非敏感导入导出 | 15分钟 | 5分钟 |
| 缺口确认和签字 | 15分钟 | 10分钟 |
| 合计 | **90分钟** | **45分钟** |

第一至第三阶段整体Review仍建议按总指南预留**5小时完整Review**或**3小时核心Review**；本文件的90分钟已经包含在其中第一阶段部分，不需要重复累计。

## 7. 人工UAT路径

前置条件：仅使用`REVIEW-`或`UAT-`开头的合成人员；按[密钥运行手册](../implementation/personnel-sensitive-key-runbook.md)向本机运行进程注入测试密钥，不在截图或记录中保存密钥。

1. 新建一名合成人员，只填法定姓名，确认展示姓名自动默认且工号为六位数字。
2. 新增四类主体关系，先使用同一法人，再为其中一种新增未来生效版本；切换查看日期核对结果和历史。
3. 不先建证件，直接创建待入职劳动关系，应被`VERIFIED_PRIMARY_DOCUMENT_REQUIRED`拒绝且不占用工号。
4. 新增一张合成主要证件并将校验状态更正为“已核验”，再创建待入职劳动关系，应成功并取得六位工号。
5. 新增合成联系方式、地址和紧急联系人，确认列表只有脱敏值；更正一个敏感值时，原明文不得自动回填。
6. 更正证件到期日并填写原因，再将一条联系信息有因失效；确认记录仍可查询、有效期改变且有审计，不出现物理删除。
7. 不填原因尝试Reveal，应被阻止；填写`REVIEW安全验收`后查看一次，确认关闭弹窗后明文不再显示。
8. 新增教育、工作和家庭记录，确认同样只显示脱敏值，并可更正或失效。
9. 下载`person_basic`模板，加入一个敏感列后预校验，应被拒绝；删除该列后导入合成人员并导出当前快照。
10. 使用无Reveal权限角色重复第7步，应返回拒绝；本轮如只配置主管理员，可将此项记录为“待角色细分UAT”。

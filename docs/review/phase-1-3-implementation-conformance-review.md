# coreHR 业务第一至第三阶段实现符合性审查

> 审查日期：2026-08-09
> 审查范围：`main` 分支当前代码、本机 Docker 业务栈、PostgreSQL 测试库、正式基线文档
> 审查结论：主管理员工程 MVP 已具备连续演示和业务验收条件；尚不能作为生产替换系统上线

## 1. 审查口径

本报告回答三个问题：

1. 已确认需求是否已经进入系统。
2. 文档、数据库、API、管理端和测试是否相互一致。
3. 哪些内容仍需要企业资料或专项验证，不能被误报为完成。

状态定义：

- `PASS`：核心闭环已实现，并有自动化测试或本机整栈证据。
- `PARTIAL`：通用骨架和核心操作已实现，但企业规则、字段或自动衔接尚未齐全。
- `HOLD`：已明确延期，不属于当前一至三阶段完成声明。

本次没有上传或复制企业真实人员数据。自动化测试、Docker 联调和浏览器验收均使用本机环境及合成数据。

## 2. 总体结论

| 范围 | 状态 | 当前可用程度 |
|---|---|---|
| 平台公共能力 | PASS | 主管理员、登录、角色权限、审计、统一错误、流水号、迁移链可用 |
| 第一阶段 Core HR | PARTIAL | 组织、人员、劳动关系、任职、编制、招聘需求可以由管理员操作；批量初始化和完整企业字段仍待补 |
| 第二阶段人员生命周期 | PARTIAL | 流程执行、审批任务、应聘、协议及人事事件执行/回退闭环可用；真实审批图和完整合同字段仍待补 |
| 第三阶段考勤 | PARTIAL | 规则、班次、排班、打卡、请假、日报和月报闭环可用；企业细则、余额、设备及万人容量仍待补 |
| 生产替换条件 | 未达到 | 尚缺真实规则验收、正式数据迁移、权限细分、安全部署、容量和灾备验证 |

当前最准确的产品定义是：**可供 HR 系统主管理员连续试用的一至三阶段工程 MVP**。它不是只有表结构的空壳，也不等于已完成生产上线验收。

## 9. 下一轮请按顺序补充

这些输入不会阻塞现有工程 MVP 使用，但会依次决定企业适配质量：

1. **正式编码对照表**：法人、组织类型、历史组织、员工类型/状态、职务/职级/职等/职类/序列、协议类型。
2. **第一阶段字段验收表**：人员档案、待入职档案、劳动/协议关系、任职、编制和招聘需求的必填、可见、可编辑、唯一性要求。
3. **数据迁移验收样例**：在本机提供脱敏小批量样例和期望结果，不需要上传云端；先做字典→组织/法人→人员→任职→编制。
4. **人事流程图**：依次提供入职、转正、调动、兼岗、借调、离职、撤回/更正；每个节点注明会签/或签、处理人、条件和超时规则。
5. **合同/协议表头和规则**：类型、编号、期限、签署、续签、变更、解除、预警和附件要求。
6. **考勤规则包**：班次、迟到早退、缺卡、跨日、排班、假期、请假/销假、日报和月报样例及冻结时点。
7. **打卡接口契约**：来源、认证、幂等键、时间戳、设备/位置证据、补传和失败重试。
8. **非功能验收基线**：8GB/32GB 服务器、备份恢复、日志保留、安全边界，以及一万人同时打卡/查询的具体流量模型。

第 1 项完成后，即可优先启动第一阶段正式初始化工具；第 4 项完成后替换示例流程；第 6–7 项完成后，第三阶段结果才能进入业务口径验收。

## 10. 当前验收建议

建议本轮只批准：

- “主管理员工程 MVP 可进入业务 UAT”；
- “一至三阶段通用核心链路已实现”；
- “后续按本报告第 9 节补企业输入并逐项关闭 `PARTIAL`”。

暂不批准：

- 生产系统替换；
- 正式企业数据全量迁移；
- 普通员工、自助端或细分角色开放；
- 考勤结果进入薪酬；
- 一万人并发、灾备和多数据库兼容性达标声明。

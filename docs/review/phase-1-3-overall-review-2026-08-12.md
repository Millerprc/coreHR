## 1. Review 结论

当前系统不是只有数据库表和接口的空壳。主管理员已经可以通过管理端连续操作公共能力、第一阶段 Core HR、第二阶段人员生命周期和第三阶段考勤的主要技术链路。

本轮可以批准：

- 主管理员工程 MVP 进入业务 UAT。
- 第一至第三阶段通用核心链路继续作为企业适配基础，不需要推翻重做。
- 主管理员能够创建 SSC 账号、分配角色、启停访问；SSC 账号可以登录并获得已配置权限。
- 后续按本文的待确认顺序补真实规则，并逐项关闭 `PARTIAL`。

本轮不能批准：

- 替换生产 HR 系统或迁移全量真实数据。
- 将示例流程视为企业正式审批流程。
- 将当前考勤结果直接送入薪酬核算。
- 向普通员工开放自助端，或声明细分数据权限已经完成。
- 声明一万人同时打卡/查询、灾备、多数据库或中间件兼容已经达标。

因此，当前最准确的产品状态是：**业务第一至第三阶段的主管理员工程 MVP 已实现，企业规则适配和业务 UAT 尚未完成。**

## 2. 状态口径

| 状态 | 含义 |
|---|---|
| `IMPLEMENTED_VERIFIED` | 已有数据库、服务端规则、API、管理端入口及自动化或本机整栈证据 |
| `PARTIAL` | 通用能力可用，但企业字段、审批图、计算规则、连接器或权限范围尚未补齐 |

## 3. 本轮最近任务完成情况

### 3.1 账号与权限管理

状态：`IMPLEMENTED_VERIFIED`

主管理员新增“账号与权限”工作区，当前可以：

- 查看有效角色和账号列表。
- 创建本地账号，默认可选择 `SSC_ADMIN`。
- 分配或调整一个账号的角色。
- 停用和重新启用账号，并强制填写操作原因。
- 阻止停用当前登录账号。
- 阻止停用或移除最后一个有效 `SYSTEM_ADMIN`。
- 停用账号时永久撤销其所有既有会话；重新启用后旧令牌不会恢复有效。
- 对创建、角色调整和启停写入审计日志；密码不进入响应或审计日志。

当前有意未实现：

- 首次登录强制修改初始密码、管理员重置密码和密码过期策略。
- User 与 Person 的管理端关联操作。
- 数据范围和字段级角色配置界面。
- 企业微信统一身份认证。

这些缺口不阻塞主管理员为 SSC 创建可登录账号，但在扩大用户范围前必须补齐。

### 3.2 入职事件安全前置能力

状态：`PARTIAL`

已经实现：

- 只有 `pending_start` 劳动关系可以创建或执行 `ONBOARDING` 事件。
- 同一劳动关系不能并行存在多个未结束的入职事件。
- `SSC_ADMIN` 拥有独立的 `ONBOARDING_INITIATE` 权限，主管理员通过通配权限操作。
- 发起原因不能为空，并写入审计日志。

仍未完成：入职生效日期口径、正式审批节点、动态办理人、条件分支和 SSC 专用入职工作台。因此不能把上述保护规则解释为“企业入职流程已交付”。

## 9. 原型 `06-nav-system.html` 复用判断

结论：**可以复用设计思想和信息架构，不能把 HTML 文件直接并入当前 React 管理端。**

可复用部分：

- 按“组织、人员、编制招聘、流程、考勤、系统”等业务域分组的导航结构。
- 二级菜单、待办数字、命令面板和模块总览的交互概念。
- 字体、颜色、间距、边框阴影和状态色等设计令牌。
- “用户与权限、角色管理、字典/编码、数据导入、审计日志、系统设置”的系统域拆分。

不能直接复用的原因：

- 原型是约 58 KB 的纯静态 HTML/CSS，没有 React 组件、路由、权限过滤、状态管理或 API 连接。
- 原型包含第四阶段和尚未实现的模块；直接照搬会让用户看到假入口。
- 当前管理端使用 Ant Design，需要把原型令牌映射为 Theme Token，并把导航定义映射到现有权限代码。

建议时机：完成入职流程规则确认后，单独建立“导航与设计系统迁移”任务；先迁移分组和视觉令牌，再逐个开放真实功能，未实现模块不显示。

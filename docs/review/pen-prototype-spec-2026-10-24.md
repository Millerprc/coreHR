### 1.2 关于「中文没有渲染成功」的诊断结论

用户反馈 `.pen` 文件「中文都没有渲染成功」。经逐层取证，**该现象在当前环境下无法复现，文件与渲染链路均正常**：

| 检查项 | 方法 | 结果 |
|---|---|---|
| 文件内中文字节 | `json.loads` + U+FFFD 替换字符计数 | **0 个**，全部是合法 UTF-8 |
| 文件编码 | BOM 检测 | 无 BOM，UTF-8 标准 |
| 画布渲染 | `Export` 导出 2× PNG 实拍 | 中文**全部正常渲染**（组织管理/汇报关系/编制管理/人员中心/操作日志…） |
| 字体变量 | `GetVariables()` | `$corehr-font` → `Noto Sans SC`（唯一合法且支持中文） |
| 字体可用性 | Windows 已安装字体枚举 | `Noto Sans SC` 已安装（含 Medium/DemiLight 等 7 个字重） |
| 字体回退 | 6 组字体探针对比 | `Microsoft YaHei` / `Source Han Sans SC` / `PingFang SC` 在 Pencil 中被判定 **invalid**；仅 `Noto Sans SC` 与 `Inter` 合法 |
| Google Fonts CDN | `Invoke-WebRequest` 拉 CSS + 字体文件 | CSS 336 KB / 101 个 gstatic URL；字体文件 HEAD **200**，298 ms |
| VS Code 编码设置 | `settings.json` 检查 `files.encoding` | **未配置**（默认 UTF-8） |

> **结论**：`.pen` 的中文数据、字体变量、渲染器、字体文件四条链路全部健康。
> 如果用户当时看到中文异常，最可能是 **VS Code Pencil 扩展首次打开时字体尚未加载完成**（Google Fonts 需异步拉取 336 KB CSS + 101 个子集文件）。
> **规避建议**：保持 `$corehr-font = Noto Sans SC` 不变；首次打开画布时等待字体加载完成再判断；不要改用 `Microsoft YaHei` 等本地字体名（Pencil 判定为 invalid，会退化渲染）。
>
> ⚠️ **另注**：在 PowerShell 控制台里读 `.pen` 看到中文乱码，是 **PS 控制台按 GBK 输出**所致，**不是文件缺陷**。判定编码必须用 Python 读字节、或用 Pencil `Export` 实拍，不能以控制台显示为准。

## 4. 各画板设计要点

### 4.1 职位管理（`op8Nx`）

- **页头**：标题「职位管理」；副标题与 `PositionWorkspace.tsx:523-531` 逐字一致。
- **指标条**：有效职位 / 职级 / 职等 / 职类 / 序列（`:549-553`）。
- **Tabs**：职位列表（激活） / 职务维度。
- **筛选区**：生效日期（日期框，2026-10-24）+ 搜索（占位「搜索职位名称或编码」）+ 重置 + 查询。
  - 对齐实现差异：职位页「重置」**不重置生效日期**（`:543-546`），已在设计中保留生效日期输入框。
- **表格 10 列**：职位编码 / 职位名称 / 职级 / 职等 / 职类 / 序列 / 生效日期 / 版本 / 状态 / 操作（新增版本）。
  - 生效日期渲染为「2026-01-01 至 长期」（对应 `effective_from` 至 `effective_to ?? "长期"`）。
  - 状态 Tag：启用（success 绿）。
- **分页**：共 1 个职位，每页 20，`showSizeChanger: false`。

### 4.2 汇报关系（`b5PHy`）

- **页头**：标题「汇报关系」；副标题说明实线/虚线语义（`:407-421`）。
- **主操作**：右上「新增关系」按钮（primary）。
- **Tabs**：关系管理（激活） / 关系图。
- **筛选区**：生效日期 + 上级（全部上级）+ 下级（全部下级）+ 重置。
  - 上级/下级为 PersonSelect 远程搜索，画板用下拉形态示意。
- **表格 6 列**：上级 / 下级 / 关系类型 / 生效日期 / 失效日期 / 操作（结束）。
  - **关系类型双态区分**：直属（蓝 `#E6F4FF`/`#0958D9`）、虚线（紫 `#F9F0FF`/`#531DAB`）——这是 D-093 的核心语义，视觉上必须一眼可辨。
  - 失效日期空值渲染为「长期有效」（`:536`）。
  - 操作列「结束」为 danger 链接（实现中带 Popconfirm）。
- **数据**：2 行演示数据（张伟→李娜 直属 / 李娜→王强 虚线）。

### 4.3 操作日志（`laZ5d`）

- **面包屑**：数据治理 / 操作日志（独立入口，不在组织管理分组）。
- **页头**：标题「操作日志」；副标题强调只读（`:268-278`）；右上「导出CSV」次按钮（仅管理员可见）。
- **无 Tabs**——本页是纯只读宿主页（实现中明确无 Modal/Drawer/新标签页）。
- **筛选区 6 项草稿式**：时间范围 / 操作类型 / 对象类型 / 追踪 ID / 操作人 + 查询/重置。
  - 对齐实现：草稿式筛选改值不立即查询，点「查询」才生效（`applyFilters`，`:237-240`）。
  - 与职位/汇报关系页的差异：此处「重置」**重置全部筛选**。
- **表格 8 列**：时间 / 操作人 / 操作 / 对象类型 / 对象 ID / 追踪 ID / 来源 / 原因。
  - **action / object_type / source 是后端原始代码，前端不做中文映射**（`AuditLogWorkspace.tsx:138`），画板据此使用英文原值（如 `position.update`、`web`），未擅自翻译。
  - 操作 Tag 蓝（processing 类）、来源 Tag 橙（warning 类）。
- **分页**：共 128 条，**支持页长切换**（20/50/100）——四页中唯一。

### 4.4 人员中心（`JN45s`）

## 5. 与现有实现的差异说明（供前端对齐时注意）

以下是**有意保留**的实现特征，画板未按「理想形态」美化：

| # | 差异 | 依据 |
|---|---|---|
| 1 | 职位页「重置」不清空生效日期；日志页「重置」清空全部筛选 | 两页语义本就不一致，画板分别体现 |
| 2 | 操作日志的 action / object_type / source 保持英文原值 | 前端不做中文映射 |
| 3 | 职务维度 Tab 的分页是静态的（只显示首 20 条） | `PositionWorkspace.tsx:620-624` 无 `current`/`onChange` |
| 4 | 标签类型与标签项文案全部来自接口，画板用示意值 | `label-api.ts:4-6` 前端不硬编码 |
| 5 | 职位载荷的 `source_job_id` / `attributes` 在表单中无控件 | API 契约有但表单无，画板不加 |
| 6 | 员工标签在 Drawer 内，不设独立路由 | `PeopleWorkspace.tsx:213-289` |
| 7 | 编辑/修正**不是** Modal 套 Drawer，而是同一 Drawer 的内联态 | 规范 §4.3 禁嵌套两层业务容器（D-106） |
| 8 | 修正态的「登记值」与「当前生效值」两栏内容相同 | 演示员工无修正记录，如实呈现 |
| 9 | 历史花名册的时点字段只在有区间化数据/修正版本的字段上生效，未修正字段等于当前值 | D-102 的能力边界，画板以提示条明说 |
| 10 | 历史花名册演示的是 `2024-01-01`，实现的默认时点是今天 | 画板用历史时点以体现「时点切片」语义 |

### 8.1 历史组织架构 · 查看日期（D-103）—— 缺口 C23

**宿主**：部门管理 → 组织架构树页签（`OrganizationWorkspace.tsx`）+ 组织详情页（`OrganizationDetailWorkspace.tsx`）。
**载体**：`HOST_PAGE`（1440×960），**不是**新建独立页面（D-103 明确不建独立待生效页）。

| 位置 | 元素 | 说明 |
|---|---|---|
| 树面板标题 | 标题文案 | 当前时点＝「当前有效组织树」；历史时点＝「截至 YYYY-MM-DD 的组织树」 |
| 树面板 | 树的无障碍 label | 随时点同步变化（`OrganizationTree.tsx` 动态 aria-label） |
| **树右侧详情面板顶部工具条**（`.detail-toolbar`） | **「查看日期」控件** | 复用 `EffectiveDatePicker.tsx`，标签「查看日期」，原生日期输入；**不新写日期控件**（D-091） |
| 查看日期控件右侧 | 状态标签 Tag | 「当前」（默认灰）/「截至 YYYY-MM-DD」（processing 蓝） |
| 状态标签右侧 | 文字按钮 | 历史时点时出现「回到当前」 |
| **列表页签筛选区** | 只读状态 Tag | 放在「重置」按钮左侧，说明列表同样随该时点切片（列表「重置」仅清搜索与类型，不动日期） |

**交互**：切换日期**立即重新取数**（树 + 详情 + 关系 + 财务维度），**无「查询」按钮**。
**状态规则**：当天 = 当前时点（请求不带 `as_of`）；历史日期 = 历史时点（带 `as_of`）；未来日期 → 后端 422 `CURRENT_OR_HISTORY_TREE_ONLY`，界面用既有错误条显示「只支持查看当前与历史时点的组织架构」。

**为什么日期控件放在树/详情头部而不是筛选区**：该页筛选区只服务「列表」子页签，把日期放进它会导致树页签看不到控件。

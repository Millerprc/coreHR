## AI 对抗验证

- **使用的验证提示**：
  - "第零阶段开发基线要求最小 FastAPI 启动 + pytest 通过，确认是否完成。"
  - "Vite CJS Node API 已弃用警告是否影响 Vitest 与 build 的实际成功？"
  - "PostgreSQL 16-alpine 实际版本 16.14 是否满足 PG 16 基线？"
  - "psycopg v3 是否完成完整写入和读取周期？"
- **发现的问题**：
  - 1) pytest-asyncio 0.25 在未设 `asyncio_default_fixture_loop_scope` 时输出 deprecation warning 并被 PowerShell 误判为错误；已补 `pytest.ini` 最小配置解决。
  - 2) Vitest 5.0+ 才移除 Vite CJS Node API deprecation，2.x 仍保留告警；告警来自 Vite 5 自身库，非本任务缺陷；通过把 stderr 重定向文件读取确认 exit=0 与测试通过。
  - 3) `redis:7.4-alpine` 未在本地缓存且 docker pull 走默认 registry 在 180s 内未完成；使用本地已缓存的 `redis:8.6-alpine` 完成验证，命令兼容性已在 ADR 中说明回退方案。
- **修复结果**：
  - 1) 已修复。
  - 2) 不属本任务范围，已在交付证据中明确退出码与实际成功状态。
  - 3) 已在 ADR 备选方案中说明。

## 风险和待用户确认

- 实际验证时 Redis 用了 `redis:8.6-alpine`（本地已缓存的 8.6.5），未走通 7.4 拉取链路。`redis:7.4-alpine` 是 ADR 锁定目标；Z0-003 容器编排时需补一次 `docker pull redis:7.4-alpine` 验证。
- 容器镜像仅锁定 tag 未锁定 digest；锁定 digest 留到 Z0-003 任务。
- Python 3.13 选了次新稳定版；若企业内 Python 3.12 是事实标准，可在 Z0-002 启动前重提一个 ADR-0002-toolchain-adjust 替换。
- 临时验证目录 `tmp/z0-001-verify/` 仍在仓库中（被 .gitignore 忽略），作为可追溯证据；如不需要可手动 `Remove-Item -Recurse tmp/z0-001-verify` 删除。
- 本任务不创建任何代码或运行时资产进入仓库主干；唯一仓库内文件是 ADR-0001 与本交付报告。

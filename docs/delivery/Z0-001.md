### 第一轮复跑中暴露、第二轮已修复的问题

| 问题 | 原因 | 第二轮修复 |
|---|---|---|
| `docker compose wait pg redis` 卡死 | `wait` 等待容器退出，PG/Redis 不会退出 | 改 `docker compose up -d --wait pg redis` |
| `docker compose up --abort-on-container-exit` 误停 web | backend 跑完正常 exit 触发整体停，web 启动即被 SIGKILL（退码 137） | 脚本分阶段：`run backend` → `run --no-deps web` |
| `vitest run` 默认 31 worker 在 Windows bind mount 挂起 | 默认并发高、bind mount I/O 重 | `vitest run -- --maxWorkers=1 --minWorkers=1`，耗时约 103 秒 |
| Python 间接依赖（starlette / anyio / certifi 等）未哈希锁 | 仅锁直接依赖 11 个 | 生成 `requirements.lock`：31 个包 + sha256，容器 `pip install --require-hashes` |
| 容器镜像用移动 tag `python:3.13-slim` | minor 浮动风险 | 改 `python:3.13.14-slim` 精确 patch |
| 脚本失败后可能残留容器 | 无清理逻辑 | POSIX `trap cleanup EXIT`，PowerShell `try/finally` 跑 `docker compose down -v` |
| PowerShell 未明确 cd 到 evidence 根 | 找不到 compose 文件 | `Set-Location (Split-Path -Parent (Split-Path -Parent $PSCommandPath))` |
| README 与交付报告把 `--abort-on-container-exit` 当作推荐备用命令 | 误导 | 全部删除并加反例说明 |

# P1 有效日期职务体系交付回执

> 交付日期：2026-08-12
> 状态：`GENERIC_CAPABILITY_COMPLETE / ENTERPRISE_CATALOG_PENDING`
> 范围：第一阶段职务维度、职务目录、导入导出及跨阶段引用校验

## 1. 交付结果

- 职级、职等、职类、序列成为四类独立稳定主数据；父级关系可选，不假设企业一定是固定一对一层级。
- 维度名称、父级、顺序、状态和备注按生效日期新增版本，稳定代码不随名称变化。
- 职务稳定代码引用四类在目标日期有效的维度，名称、组合、状态、来源 ID、备注和扩展属性按版本保存。
- 管理端“人力与编制 → 职务体系”可按日期查看、新建维度/职务和新增未来版本。
- 任职、月度编制、招聘需求和人事调动会拒绝目标日期不存在或未启用的职务；招聘目标月份按“目标月首与当前业务日孰晚”校验，不与编制强绑定。
- 数据治理新增“职务维度”类型；职务维度父级可在同批次乱序出现，执行前自动拓扑排序；职务引用未知、停用或未生效维度时逐行拒绝。
- 数据治理新增“职务维度历史版本”和“职务历史版本”两类导入任务；同一稳定代码的多行可乱序提交，执行时按生效日期和父级依赖追加，并复用版本闭合、并发校验、审计和兼容投影逻辑。
- 当前有效职务维度和职务可按指定业务日期导出；表格公式注入防护和既有来源追踪机制继续生效。

## 2. 数据库与兼容边界

- 新增 `job_dimensions`、`job_dimension_versions`、`job_catalog_versions` 三张表。
- 既有 `job_catalog.id` 继续作为编制、招聘和任职引用的稳定身份，避免破坏已交付外键和数据。
- `job_catalog` 旧字段暂保留为兼容投影；按日期查询以版本表为事实来源。
- 从 `f3a000000004` 升级时，旧职务及四类代码自动回填为首版本；缺少正式中文名称的旧维度暂以代码显示，等待企业码表修订。
- 本机已有数据升级曾暴露 JSON 类型绑定缺陷；修复后事务化重跑成功，未留下半迁移状态。

## 3. 页面与原型复用

`tmp/ui-mockup/06-nav-system.html` 可作为导航密度、模块分组和非技术管理端表达的参考。实际实现沿用现有 Ant Design 设计系统和“页面标题—查看日期—主操作—页签表格—版本弹窗”的组件结构，没有直接复制原型的静态代码，避免形成第二套样式和交互规范。

## 5. 当前边界

- 企业正式职务、职级、职等、职类、序列代码和名称尚未输入，因此通用功能完成不等于企业码表验收完成。
- CSV 支持每个稳定代码的首版本初始化和后续多段版本批量追加；后续版本必须晚于数据库最新版本，并填写变更原因。
- 倒插历史、批次回滚和历史全量导出仍属于迁移适配工作；更早的遗留版本需在收到真实历史表后设计专用离线迁移规则。

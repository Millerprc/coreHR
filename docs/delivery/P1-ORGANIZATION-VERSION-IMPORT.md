# 第一阶段组织历史版本导入交付回执

> 日期：2026-08-13
>
> 范围：已有组织稳定编码之后的有效日期版本批量导入
>
> 状态：`IMPLEMENTED_AND_VERIFIED`

## 1. 已交付

- 新增“组织历史版本”CSV任务，字段包括组织稳定编码、名称、组织类型、上级组织、国家/地区、状态、生效日期和逐行变更原因。
- 只允许在已有组织最新实际版本或计划版本之后向前追加，不允许借通用入口倒插或重写既有历史。
- 同一批次中同一组织的多行按生效日期顺序执行；涉及父子组织时，按日期和父级依赖排序。
- 校验组织、组织类型和父级稳定编码；父级必须在目标生效日期存在且处于启用状态，并阻止组织环。
- 已到业务日期的版本立即生效并自动闭合上一版本；未来日期版本保留为计划事件。
- 每一行使用稳定来源身份生成领域幂等键；同来源同内容重放跳过（即使该来源事件后来被取消），同来源内容变化拒绝。取消后需要同日替代时必须使用新的来源记录ID。
- 执行时会重新读取来源追踪记录，两个批次即使都先完成校验，后执行的相同来源仍会安全跳过；领域事件命中幂等键时必须同时匹配组织、生效日、版本、内容和变更原因。
- 复用组织领域服务写入版本事件、审计日志和下游事件，不由导入服务复制版本算法。
- 管理端导入类型中显示“组织历史版本”；当前有效快照导出不包含该历史任务。

## 2. 操作顺序

1. 先用“组织”任务导入每个组织的首个有效版本，保留旧系统稳定编码。
2. 再选择“组织历史版本”下载模板。
3. 每行使用可长期稳定的来源记录ID，并填写该版本自己的变更原因。
4. 先校验批次；确认全部父级、类型、日期和环校验结果后再执行。
5. 对未来版本，在组织版本事件中检查计划状态；到达业务日期后按既有事件应用机制生效。

## 3. 安全边界

- 本任务只处理组织版本，不接收人员、证件、联系方式、薪酬或附件。
- 不接收 `effective_to`；结束日期由下一版本自动闭合，避免外部数据制造重叠版本。
- 不支持早于或等于现有最新版本日期的新增来源记录。需要倒插历史时必须另行设计离线迁移和冲突处理方案。
- 历史版本不是当前快照导出类型；现有“组织”导出仍只输出指定业务日期的有效状态。
- 不提供物理删除或批次回滚；更正应通过新的版本事件完成。

## 4. 自动化验收

- 后端专项覆盖：乱序多版本追加、上一版本自动闭合、逐行原因、未来计划事件、来源重放跳过、未知组织、倒插日期、未知类型、缺失父级和停用父级。
- 前端专项覆盖：导入选择项可见，导出选择项不可见，TypeScript 类型检查通过。
- 完整工程回归结果记录在本次提交对应的 Review 报告中。

- 人员关系、任职、汇报、协议、标签、编制和敏感档案的完整历史迁移。
- 企业正式组织数据清洗、编码对照和业务 UAT。

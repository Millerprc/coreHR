# 第三阶段假期余额交付回执

> 日期：2026-08-09
>
> 范围：主管理员使用的年度假期余额账户、不可变流水和请假联动
>
> 状态：`IMPLEMENTED_AND_VERIFIED`

## 1. 已交付

- 假期类型支持三种余额模式：不跟踪、记录且允许负数、余额不足时阻止批准。
- 余额账户按“员工劳动关系 + 假期类型 + 自然年度”唯一建立，单位固定为天或小时。
- 主管理员可登记额度发放、人工调整、上年结转和周期计提；每次入账必须填写生效日期和原因。
- 批准请假自动生成扣减流水；批准销假或直接取消已批准请假时自动生成冲回流水。
- 重复批准、重复冲回和重复提交同一人工入账不会重复改变余额。
- 管理端新增“假期余额”页签，可查看当前余额、账户版本和完整流水。

## 2. 数据与并发规则

- 新表：`leave_balance_accounts`、`leave_balance_transactions`。
- 流水只追加、不修改、不删除；每条流水保存变动前余额、变动后余额和账户版本。
- 人工入账要求调用方提供幂等键；同一幂等键用于不同内容时返回冲突。
- 同一账户的并发变动使用事务级锁串行化，不同员工、假期类型或年度可并行。
- “余额不足不批准”在同一事务内校验；失败时请假状态和余额均不改变。
- 已产生余额账户后不能修改假期类型的计量单位，避免历史余额失真。

## 3. 明确边界

- 跨自然年的受管假期需拆为两个申请，避免在企业折算规则未确认时猜测年度分摊。
- 当前已提供可审计的“计提”和“结转”人工入账能力，尚未固化自动计提频率、入职折算、封顶、清零和跨年结转公式。
- 假期余额模式变更只影响后续批准；历史流水不重算。
- 当前能力仅开放给 `ATTENDANCE_ADMIN`，普通员工自助查询与申请不在本期范围。

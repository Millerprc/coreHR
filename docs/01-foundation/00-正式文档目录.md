## 2. 当前实现与开发边界

已经实现并可继续迭代：

- 第零阶段工程、账号权限、审计、流水号、运行与测试底座。
- 第一阶段组织、法人及关系、人员、劳动/协议关系、任职、编制、快照和招聘需求核心链路。
- 第二阶段流程执行、审批任务、候选人/应聘、合同基础信息及人事事件执行/回退核心链路。
- 第三阶段考勤规则、班次、排班、打卡、请假/销假、日报和月报核心链路。
- 主管理员PC管理端；移动尺寸可以访问，但不代表员工移动门户已交付。

必须取得企业输入后再固化：

- 正式编码枚举、完整人员档案字段和批量数据迁移规则。
- 企业审批图、审批人表达式、完整合同/协议规则。
- 企业考勤、假期、设备接入及月结冻结细则。
- 企业微信、自建OA和其他下游连接器。

明确延期到第五阶段：多国家/语言、多租户、MySQL/Oracle兼容、应用服务器中间件和员工移动门户。当前真实完成度以[一至三阶段整体Review报告](../review/phase-1-3-overall-review-2026-08-12.md)为准。

## 3. 文档关系

```text
coreHR产品总体PRD（父级权威入口）
  ├─ 模块功能需求文档规范
  │    └─ 模块 → 能力域 → 功能 → 验收场景 → 最小任务
  ├─ 项目决策
  ├─ 迁移输入：第一阶段需求规格
  │   ├─ 组织与主体领域规范
  │   ├─ 编制与人力结果领域规范
  │   ├─ 人员档案领域规范
  │   └─ 人事数据与事件规范
  ├─ 迁移输入：第二阶段需求规格
  ├─ 迁移输入：第三阶段需求规格
  ├─ 代码结构与编码规范
  ├─ Ant Design页面与交互载体规范
  └─ 待确认问题

历史归档
  └─ 旧项目基线 / 阶段PRD / 旧技术架构 / 已完成开发基线
```

发生冲突时按以下顺序处理：

1. 用户最新明确确认。
2. [16-coreHR产品总体PRD.md](./16-coreHR产品总体PRD.md)中的产品级边界。
3. [03-项目决策.md](./03-项目决策.md)中的`CONFIRMED`业务决策；若与父PRD的产品级边界疑似冲突，停止开发并提交产品决策人处理。
4. [17-模块功能需求文档规范.md](./17-模块功能需求文档规范.md)以及按该规范批准的模块功能需求。
5. [Ant Design页面与交互载体规范](../design/antd-page-interaction-standard.md)和[10-代码结构与编码规范.md](./10-代码结构与编码规范.md)的当前实现约束。
6. 对应迁移输入中的已确认业务事实；若尚未迁移到批准的功能文档，不得直接开工。
7. 实施计划和交付回执。
8. 历史归档和技术草案；仅用于追溯，不得覆盖现行权威。

## 4. 状态说明

| 标识 | 含义 |
|---|---|
| `CONFIRMED` | 用户已明确确认，可以进入需求基线 |
| `READY_FOR_ASSIGNMENT` | 已具备分配条件，但仍按任务依赖逐项开工 |
| `PARTIAL` | 方向已确认，字段或边界仍需补充 |
| `IMPLEMENTED_GENERIC` | 已有通用工程实现，但尚未通过企业规则UAT |
| `ENTERPRISE_INPUT_PENDING` | 企业字段、流程或计算规则未确认，不得生成最终业务实现任务 |
| `PENDING` | 尚未确认，不得作为开发依据 |
| `DEFERRED` | 已明确推迟到后续阶段 |
| `HISTORICAL_INPUT` | 保留为后续功能文档的页面、旅程和业务输入，不能单独扩大开发范围 |
| `REVIEW_PENDING` | 已形成可Review基线，等待产品决策人正式批准 |
| `MIGRATION_INPUT` | 仍含可复用业务事实，需迁移到新功能文档后才能形成新开发依据 |
| `ARCHIVED` | 已被新基线替代，仅用于历史追溯和提取输入 |

## 5. 第一阶段企业适配前条件

第一阶段通用核心能力已经实现。进入正式数据迁移和企业验收前仍需：

1. 提供稳定业务键、正式枚举和历史编码对照。
2. 冻结人员档案等模块的字段验收表、权限和敏感级别。
3. 在本机使用脱敏小批量样例验证导入、拒绝、重复执行和回滚。
4. 按[实现符合性审查](../review/phase-1-3-implementation-conformance-review.md)逐项关闭 `PARTIAL`。

未决资料只阻塞其影响的企业适配项，不阻塞已完成工程 MVP 的主管理员 UAT。

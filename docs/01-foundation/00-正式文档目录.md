## 2. 当前开发边界

当前允许MinimaxCode开发：

- 工程结构和本地运行环境。
- 前后端基础工程。
- 数据库迁移和公共API规范。
- 本地账号、权限底座、通用字典和编码序列。
- 审计、有效期、导入导出、任务与运行观测基础能力。
- 自动化测试与第零阶段端到端冒烟验证。

当前不允许开发：

- 完整组织、法人、成本中心、收入目标业务功能。
- 职务体系和编制业务。
- 招聘需求状态机。
- Person、Employment和完整人员档案。
- 人事流程、快照业务和事件回退算法。
- 企业微信、OA、移动端、MCP、多租户和微服务。

具体任务、依赖和验收以[09-MinimaxCode第零阶段开发基线.md](./09-MinimaxCode第零阶段开发基线.md)为准。

发生冲突时按以下顺序处理：

1. 用户最新明确确认。
2. [03-项目决策.md](./03-项目决策.md)中的`CONFIRMED`决策。
3. [09-MinimaxCode第零阶段开发基线.md](./09-MinimaxCode第零阶段开发基线.md)对第零阶段任务的明确约束。
4. 对应领域规范。
5. 第一阶段需求规格。
6. 第一阶段PRD。
7. 技术草案。

## 4. 状态说明

| 标识 | 含义 |
|---|---|
| `CONFIRMED` | 用户已明确确认，可以进入需求基线 |
| `READY_FOR_ASSIGNMENT` | 已具备分配条件，但仍按任务依赖逐项开工 |
| `PARTIAL` | 方向已确认，字段或边界仍需补充 |
| `PENDING` | 尚未确认，不得作为开发依据 |
| `DEFERRED` | 已明确推迟到后续阶段 |

## 5. 第一阶段业务开发前条件

第零阶段工程底座可以先行开发。第一阶段对应业务模块开工前仍需：

1. 关闭该模块相关的待确认问题。
2. 提供该模块依赖的真实表结构、字段、枚举和脱敏样例。
3. 冻结数据模型、API契约、权限和验收用例。
4. 将该模块拆成具备独立交付物和测试的原子任务。

不要求所有第一阶段问题同时关闭；未决问题只阻塞其影响的模块。

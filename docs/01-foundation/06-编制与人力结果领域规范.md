# HRIS 第一阶段编制与人力结果领域规范

> 状态：`PARTIAL`  
> 版本：v0.1-draft  
> 日期：2026-07-31

## 1. 目标

第一阶段的编制能力用于维护月度计划编制并展示人员结果，不承担招聘名额控制。

用户需要能够：

- 按组织、职务和年月维护编制数。
- 平铺查看每个月的编制、人数和差额。
- 查看月初、月末、月均及当前人员结果。
- 保留编制版本、冻结状态、月度快照和操作日志。
- 在招聘需求中参考相关结果，但不被系统阻断。

## 2. 业务边界

第一阶段包括：

- 月度编制台账。
- 人员占编规则配置。
- 当前和快照人数统计。
- 业务冻结与月结冻结。
- 导入、导出、历史和审计。

第一阶段不包括：

- 招聘空编预留。
- Offer占编。
- 无空编禁止招聘。
- 超编审批或特批。
- 编制申请、增加、减少、调拨的完整审批流程。
- 编制预警通知。

## 3. 核心维度

一条月度编制记录的业务唯一维度为：

```text
组织 + 职务 + 年月
```

其中：

- 组织必须是该月份有效的业务组织。
- 职务必须是有效职务。
- 年月使用自然月。
- 编制数为非负数，是否允许小数等待真实业务数据确认。
- 同一维度可以有多个历史版本，但同一时点只有一个当前有效版本。

第一阶段不把法人、成本中心或招聘需求加入编制唯一维度。

## 4. 建议数据对象

| 对象 | 说明 |
|---|---|
| Headcount Plan | 组织+职务+年月的编制结果 |
| Occupancy Rule | 人员类型是否计入编制的配置 |
| Headcount Freeze | 指定范围和月份的冻结状态 |
| Headcount Snapshot | 月初、月末人数与当时维度结果 |
| Headcount Change Log | 编制修改前后值、原因和操作者 |

月度编制建议字段：

- 年月。
- 组织。
- 职务。
- 编制数。
- 版本。
- 冻结状态。
- 变更原因。
- 来源批次。
- 创建与修改信息。

## 5. 占编规则

当前规则：

- 正式员工计入编制。
- 员工类型为“校招生”的人员计入编制。
- 外包、派遣、兼职、实习及其他类型当前不计入。
- 所有人员类型均进入人员主数据，是否占编由配置决定。
- 创建待入职档案并明确计划入职日期后，按适用月份进入相关人数统计。
- 调岗、离职、入职撤回等人事流程完成后，需要在其生效日期释放原占用。
- 未来生效的人事事件在未来生效日期释放或转移占用，不提前改变当前人数。

第一阶段没有完整入转调离流程时，人数结果基于有效人员档案和已生效关系计算；第二阶段再由流程事件驱动。

## 6. 指标口径

当前拟定指标：

| 指标 | 口径 |
|---|---|
| 月度编制数 | 用户维护的组织+职务+年月计划值 |
| 月初人数 | 月初快照时符合占编规则的人数 |
| 月末人数 | 月末快照时符合占编规则的人数 |
| 月均人数 | `(月初人数 + 月末人数) / 2` |
| 当前人数 | 查询时点符合占编规则的实时人数 |
| 编制差额 | `月度编制数 - 当前人数` |

月均人数可以产生小数。

年度页面展示当前月份的编制数、当前人数和差额，不把12个月人数相加。是否同时展示年度各月趋势，不影响上述口径。

待入职人员按照计划入职日期归入对应月份统计。
月初月末边界按照快照策略配置的时区计算，每个快照批次保存所用时区和边界时刻。

## 7. 统计归属

人员计入哪个组织和职务，以统计时点有效的主组织和主职务为准。

- 兼岗、借调、项目和虚拟组织默认不重复占编。
- BP服务关系不改变占编归属。
- 实线或虚线汇报关系不改变占编归属。
- 四类法人主体不改变组织+职务编制维度。
- 若未来需要兼岗分摊或多编制归属，必须新增明确规则，不得通过当前关系隐式推导。

## 8. 月度维护

### 8.1 页面维护

- 用户先选择年份和月份。
- 页面平铺显示组织+职务明细。
- 用户修改指定月份的编制数。
- 修改时填写原因。
- 保存后生成新版本和变更日志。
- 不允许修改其他月份的值作为当前月份的副作用。

### 8.2 批量导入

- 模板包含年月、组织编码、职务编码和编制数。
- 初始化导入整批校验、整批写入。
- 日常批量维护允许正确行成功、错误行返回。
- 重复导入使用幂等键避免产生重复版本。
- 错误明细包含行号、字段、错误码和修正建议。

### 8.3 导出

导出至少支持：

- 当前选择年月。
- 组织和全部下级范围。
- 编制、月初、月末、月均、当前人数和差额。
- 数据版本和冻结状态。

导出结果必须与页面使用同一统计服务和口径。

## 9. 冻结

系统区分两类冻结：

### 9.1 月结冻结

用于保护已完成月结的历史月份。规则：

- 普通维护者不能修改已冻结月份的编制。
- 授权角色可以解冻或创建修订版本。
- 解冻、修改和重新冻结均记录原因和日志。
- 不覆盖原月度快照。

### 9.2 业务冻结

用于特殊时点暂停业务调整。冻结范围由以下三个维度任意组合：

- 年月。
- 组织；选择组织时包含其全部下级。
- 职务。

未选择的维度表示该维度全部范围。冻结记录同时保存起止时间、发起人、原因和当前状态。

- 普通角色不能修改命中范围的月度编制。
- 授权角色可以解冻或调整；任何绕过冻结的调整必须填写原因并记录日志。
- 招聘需求仅显示冻结提示，不阻断创建、提交或推进。
- 多个冻结条件同时命中时，只要任一有效冻结仍存在，该数据即保持冻结。
- 冻结范围变更创建新版本，不无痕改写历史范围。

## 10. 与招聘需求的关系

- 招聘需求可以选择组织和职务。
- 页面可以展示相同年月、组织和职务的编制及人员结果。
- 招聘需求人数不预占编制。
- 无空编或超编时只展示信息，不禁止创建、提交或继续招聘。
- 招聘需求关闭或取消不改变月度编制。
- 编制变化也不自动改变招聘需求人数或状态。

## 11. 快照

月初和月末快照至少保存：

- 年月。
- 组织和职务。
- 当时有效的月度编制版本。
- 当时人数。
- 参与统计的人员范围或可复核依据。
- 生成批次、生成时间和规则版本。
- 系统按照快照策略自动生成月初和月末快照。
- 月份边界使用策略配置的时区，不使用服务器本地时区隐式计算。
- 快照保存时区、边界时刻和规则版本，配置变化不追溯覆盖历史快照。

要求：

- 快照任务可重复执行但不能静默覆盖既有结果。
- 补跑或修订生成新版本。
- 原始版本保持可查。
- 快照失败可以安全重试。
- 规则配置变化后，历史快照仍可解释当时使用的规则。
- 月结后发现错误时，先更正源业务数据。
- 原始月初、月末快照永久保留且不可直接修改。
- 授权用户生成与原版本关联的修订版本并填写原因。
- 修订版本完成复核后重新冻结。
- 修订、重新冻结和所有失败重试均写入审计日志。

## 12. 权限与审计

建议拆分以下权限：

- 查看编制和人数。
- 维护月度编制。
- 批量导入。
- 导出。
- 设置业务冻结。
- 月结冻结和解冻。
- 补跑或修订快照。
- 查看变更历史。

审计至少记录编制修改、批量导入、冻结、解冻、快照生成和修订。

## 13. 异常规则

- 组织或职务在目标月份无效时，不允许新增该维度编制。
- 组织未来换上级不改写历史月份编制。
- 人员主组织或职务缺失时，不静默计入未知维度，进入数据质量异常。
- 人员有效期重叠导致重复计数时，统计任务失败并给出异常明细。
- 规则配置变更需要记录生效日期，不能无痕重算历史。
- 删除或停用组织、职务前，需要提示关联的未来月份编制。

## 14. 第一阶段验收要点

1. 可按年月平铺维护组织+职务编制。
2. 正式和校招生按规则计入，其他类型可配置。
3. 待入职档案按计划日期进入统计。
4. 页面和导出的指标口径一致。
5. 超编只呈现结果，不阻断招聘。
6. 月结冻结后普通用户不能修改，授权操作全程留痕。
7. 月初月末快照可复核、可修订且不覆盖原版本。

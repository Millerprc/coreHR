# HRIS 项目基线

> 状态：`PARTIAL`  
> 版本：v0.1-draft  
> 日期：2026-07-30

## 1. 项目定位

建设一套企业内部使用、具备产品化标准的 HRIS。

“产品化自用”指：

- 功能、配置、权限、数据和部署具备清晰边界。
- 业务规则可配置，不把当前企业的所有常量写死在代码中。
- 每个阶段可以独立验收，并能与前后阶段稳定衔接。
- 未来可以经过适配后套用于相似业态的其他企业。
- 当前不实现多租户，多租户可行性推迟到第五阶段评估。

## 2. 建设方式

- 采用 AI Native Coding，由 MinimaxCode承担完整开发。
- 用户负责业务规则确认、阶段验收和最终决策。
- Frappe HRMS 仅作为功能与交互研究样本，不作为二次开发底座。
- 开发前必须完成需求文档、PRD和最小任务拆解。
- AI 对抗验证不能替代确定性的自动化测试和人工验收。

## 3. 企业业务背景

| 维度 | 已确认事实 |
|---|---|
| 企业规模 | 约一万人，包含正式、校招生、外包、派遣、兼职、实习等人员 |
| 业务 | 电商业态，存在持续扩张及新业务 |
| 地区 | 中国大陆、中国香港、新加坡、菲律宾、俄罗斯 |
| 法人 | 中国大陆法人超过 100 个；其他地区也存在多个主体 |
| 组织 | 业务组织树 + 虚拟组织树 + 多种人员关系 |
| 主体关系 | 组织、法人、成本中心之间存在多对多关系 |
| 首批用户 | HR 系统管理员、SSC |
| 后续用户 | HRBP、业务负责人、员工、审计等角色按阶段开放 |
| 既有数据 | 现有 HR 系统可导出数据，详细表结构后续提供 |
| 外部系统 | 企业微信、自建 OA 及其他下游系统，已有 API |

## 4. 五阶段路线

### 第一阶段：基础数据

- 基础架构
- 数据字典
- 部署架构
- 组织与职务
- 编制台账与人力结果分析
- 招聘需求
- 人事档案
- 人事数据

### 第二阶段：流程与人员生命周期

- 流程引擎
- 流程配置
- 应聘管理
- 入职、转正、调动、离职、兼岗
- 合同与协议
- 流程数据

### 第三阶段：考勤

- 考勤规则
- 考勤排班
- 假期规则
- 请假销假
- 考勤日报
- 考勤月报

### 第四阶段：薪酬

- 薪酬规则
- 社保规则
- 薪酬核算
- 社保核算
- 税务核算
- 发薪流程
- 费用分摊

### 第五阶段：平台化

- 多国家完整本地化
- 多语言
- 多租户评估与实现
- 移动门户
- 企业微信与其他入口的完整集成
- 企业级应用服务器与集成中间件评估，包括Apusic、独立API网关、消息总线和ESB等候选方案

## 5. 跨阶段原则

### 5.1 第一阶段必须提供

- 五国主体、组织和员工基础数据的录入、查询、导入、导出。
- 带生效日期的基础数据维护。
- 操作日志、敏感数据保护和数据快照。
- 为第二阶段流程引擎保留清晰的领域接口。
- 为第三、四阶段一万人同时在线场景保留水平扩展能力。

### 5.2 第一阶段不承担

- 各国考勤、休假、社保、税务和薪酬规则。
- 员工自助服务。
- 移动端独立应用。
- MCP业务入口。
- 企业微信正式身份接入。
- 多租户。
- 招聘候选人、面试、Offer和入职流程。
- 编制对招聘的强制控制。

## 6. 技术方向

以下为当前技术方向，精确版本在技术设计阶段冻结：

| 层 | 方向 |
|---|---|
| 架构 | 模块化单体，后续按压力和领域边界拆分 |
| 后端 | FastAPI |
| 前端 | React + TypeScript + Ant Design |
| 数据库 | PostgreSQL，第一阶段采用统一业务 schema |
| 缓存与任务 | Redis；后台任务按阶段引入 |
| 部署 | Linux 容器运行于服务器环境 |
| 身份 | 第一阶段本地账号密码，后续接企业微信 |
| API | 版本化业务 API；MCP以后作为受控适配层 |

### 6.1 当前明确不采用

- Frappe Custom App作为主技术路线。
- 按国家拆分五套 PostgreSQL schema。
- 第一阶段加入 `tenant_id` 和多租户逻辑。
- 仿造通用 DocType或无代码表单引擎。
- 为了“万人规模”提前拆微服务。

## 7. 容量目标

- 第一阶段8GB环境用于功能开发和业务验收，不承诺一万人同时在线。
- 项目成功后计划迁移到32GB环境。
- 一万人同时在线打卡、查询考勤或薪酬是第三、四阶段容量目标。
- 性能目标必须通过真实场景压测确定，旧文档中的500并发、1000 QPS和5000 QPS均不作为验收依据。

## 8. 第一阶段完成定义

第一阶段完成必须同时满足：

1. 已确认范围内的功能可以由 HR 系统管理员或SSC完整操作。
2. 组织、法人、成本中心、职务、编制、招聘需求和人员档案之间关系正确。
3. 五国基础数据可初始化导入并可导出。
4. 生效日期、历史版本、月初月末快照和操作审计可追溯。
5. 权限不会泄露敏感字段。
6. 数据库迁移、初始化、备份恢复和自动化测试可重复执行。
7. 第二阶段可以基于现有数据直接增加流程，不需要推翻第一阶段主数据模型。

# HRIS 第一阶段技术架构基线

> 状态：`PARTIAL`  
> 版本：v0.1-draft  
> 日期：2026-07-31  
> 读者：架构设计、开发、测试、运维

## 1. 目标

第一阶段技术架构需要支持组织与人员基础数据可靠运行，并为后续流程、考勤、薪酬和平台化阶段保留清晰扩展边界。

核心目标：

- 使用简单、可维护的架构完成第一阶段，不提前拆分微服务。
- 当前结果、有效期历史、业务事件和月度快照可以相互追溯。
- 权限能够控制功能、数据范围、字段和高风险操作。
- 初始化导入、日常批量维护、数据库迁移和备份恢复可重复执行。
- 未来可以通过水平扩展支持一万人同时在线的考勤和薪酬场景。

## 2. 总体架构

```text
Web管理端（React + TypeScript + Ant Design）
                    │
              HTTPS / REST API
                    │
模块化单体（FastAPI）
  ├─ 身份与权限
  ├─ 系统配置与数据字典
  ├─ 法人与组织
  ├─ 职务体系
  ├─ 编制与人力结果
  ├─ 招聘需求
  ├─ 自然人与雇佣
  ├─ 生效事件与快照
  ├─ 导入导出
  └─ 审计
          │                 │
    PostgreSQL           Redis
```

第一阶段采用模块化单体。模块之间通过明确的应用服务和领域接口协作，不允许跨模块任意写表。是否拆分独立服务必须由后续性能数据、故障隔离要求或团队边界驱动。

第一阶段不依赖Apusic等企业级应用服务器，也不建设ESB或独立消息总线；使用反向代理、FastAPI应用、PostgreSQL、Redis及数据库任务/出站消息表满足当前需求。相关企业级中间件统一推迟到第五阶段评估。

## 3. 技术方向

| 层次 | 当前方向 | 第一阶段约束 |
|---|---|---|
| 前端 | React、TypeScript、Ant Design | 管理端优先，暂不建设独立移动端 |
| 后端 | FastAPI | 领域模块化，业务规则不得散落在路由层 |
| 数据库 | PostgreSQL | 统一业务schema，通过主数据字段区分国家、地区和主体 |
| 缓存 | Redis | 只用于明确的缓存、限流或任务协调场景 |
| API | REST，版本化 | 第一阶段使用`/api/v1`命名空间 |
| 部署 | Linux容器 | 开发、测试、生产配置分离 |
| 身份 | 本地账号密码 | 企业微信身份接入后续实施 |
| 时间 | 数据库存UTC，界面按用户时区显示 | 日期型业务字段保持业务日期语义 |

精确版本、Python依赖管理方式、前端构建工具、数据库迁移工具和任务队列在开发启动前冻结。

## 4. 模块边界

| 模块 | 主要职责 | 禁止承担 |
|---|---|---|
| 身份与权限 | 账号、角色、权限、会话、安全策略 | 业务组织模型 |
| 系统配置 | 字典、编码规则、国家地区、币种、人员类型 | 业务交易 |
| 法人与组织 | 法人、组织树、负责人、BP、组织主体关系、成本分摊、收入目标 | 员工生命周期流程 |
| 职务体系 | 职务、职级、职等、职类、序列及关联 | 编制审批 |
| 编制与分析 | 月度编制、人数结果、差额、冻结、快照读取 | 招聘阻断和名额预留 |
| 招聘需求 | 需求创建、查询和状态跟踪 | 候选人、面试、Offer |
| 自然人与雇佣 | Person、Employment、工号、档案、组织与主体结果 | 通用流程引擎 |
| 事件与快照 | 生效事件、历史版本、月初月末快照、回退记录 | 把所有业务逻辑集中为通用低代码引擎 |
| 数据交换 | 模板、校验、批次、导入导出 | 未经授权的外部同步 |
| 审计 | 操作、敏感访问、导入导出和高风险行为记录 | 替代业务历史 |

## 5. 数据架构

### 5.1 当前结果与历史

系统需要同时保存：

1. 当前有效结果，用于日常查询。
2. 带生效区间的主数据版本。
3. 产生结果变化的业务事件或更正记录。
4. 月初、月末等时点快照。
5. 操作审计和敏感访问记录。

不得依赖单一更新时间字段还原业务历史。是否为每个领域使用独立历史表、统一事件表或组合方案，由数据模型设计决定。

### 5.2 有效期

- 有效期字段至少包含`effective_from`，需要结束日期的关系包含`effective_to`。
- 同一业务唯一维度的有效区间不得非法重叠。
- 未来生效记录不提前改变当前结果。
- 到达生效日期后必须通过可重试任务或事务内规则稳定生效。
- 所有生效和回退操作保留来源、原因、操作者和关联事件。

### 5.3 删除与停用

- 业务主数据默认不物理删除。
- 未被引用且仍处于草稿状态的数据，是否允许物理删除由各领域单独规定。
- 已生效或已被引用的数据通过停用、失效或更正处理。
- API删除操作不得通过级联误删历史、审计或快照。

### 5.4 国家与主体

第一阶段五国基础数据使用统一业务schema。国家、地区、法人、币种和证件类型作为显式字段或主数据，不按国家拆分物理schema。

完整数据驻留、本地法规隔离和多租户隔离不在第一阶段作实现承诺。

## 6. API基线

### 6.1 约定

- API统一使用`/api/v1`前缀。
- 请求和响应使用JSON；文件导入导出使用明确的文件接口。
- 列表接口统一支持分页、排序和允许范围内的筛选。
- 时间使用ISO 8601；金额同时返回数值和币种。
- 枚举值使用稳定代码，显示名称由字典或语言资源提供。
- 创建、导入、事件执行和外部回调需要支持幂等。
- 更新接口需要并发版本控制，防止静默覆盖。

### 6.2 错误响应

错误响应至少包含：

```json
{
  "code": "ORG_EFFECTIVE_PERIOD_CONFLICT",
  "message": "组织有效期与现有版本重叠",
  "details": [],
  "trace_id": "..."
}
```

- `code`供前端、测试和集成稳定识别。
- `message`面向当前用户。
- `details`用于字段级错误或批量错误。
- 不向客户端返回堆栈、SQL、密钥或内部路径。

### 6.3 批量接口

- 初始化导入先整批校验，存在阻断错误时不写入业务数据。
- 日常批量维护允许部分成功，但逐行返回结果。
- 每个批次和每行均需要可追踪标识。
- 重复提交不得产生重复业务记录。

## 7. 身份、权限与安全

### 7.1 身份

- 第一阶段使用本地账号密码。
- 密码只保存安全哈希。
- 登录失败不暴露账号是否存在。
- 支持账号停用、会话失效和登录失败审计。
- 初始管理员密码由部署过程安全设置，不进入代码或镜像。

### 7.2 授权

权限校验必须在服务端执行，至少覆盖：

- 菜单和功能。
- 新增、查看、修改、停用、导入、导出等动作。
- 组织及全部下级、法人、BP服务范围等数据范围。
- 字段查看、明文查看、修改和导出。
- 解冻、回退、快照修订等高风险能力。

### 7.3 敏感数据

- 证件、银行账户、薪酬等敏感字段按分级规则保护。
- 页面默认脱敏。
- 明文查看、导出和打印单独授权并记录访问日志。
- 加密算法、密钥托管、轮换和备份策略在安全设计中冻结。
- 日志、错误信息和测试数据不得泄露敏感字段。

## 8. 审计与可观测性

### 8.1 审计

审计记录至少包含：

- 操作者、时间、来源和客户端信息。
- 业务对象类型和标识。
- 动作、修改前值、修改后值和原因。
- 导入导出批次。
- 敏感字段明文访问。
- 解冻、回退、快照修订和权限变更。

审计记录不得由普通业务管理员修改或删除。

### 8.2 运行观测

第一阶段至少提供：

- 结构化应用日志和统一`trace_id`。
- HTTP错误率和延迟指标。
- 数据库连接和慢查询观测。
- 快照、导入、生效任务的执行结果。
- 磁盘、内存、CPU和容器健康状态。
- 关键任务失败告警。

具体监控、日志和告警产品由部署设计决定。

## 9. 部署、迁移和恢复

- 开发、测试、生产使用独立配置和凭据。
- 数据库结构变化必须使用版本化迁移。
- 初始化数据脚本可重复执行，并能识别已完成步骤。
- 发布前执行数据库备份和迁移预检。
- 必须提供备份、恢复和回滚演练步骤。
- 上传文件、数据库和密钥备份的范围分别定义。
- 8GB服务器只作为第一阶段功能开发和业务验收环境。
- 迁移至32GB或水平扩展前，根据真实数据量和访问场景压测。

## 10. 测试基线

| 层次 | 最低要求 |
|---|---|
| 单元测试 | 编码、有效期、比例、人数口径、权限等核心规则 |
| 集成测试 | API、数据库约束、迁移、导入、快照和生效任务 |
| 端到端测试 | 关键管理员操作旅程 |
| 安全测试 | 越权、敏感字段、导出、登录和高风险操作 |
| 恢复测试 | 备份恢复、任务重试、重复导入和事件幂等 |
| 性能测试 | 第一阶段关键列表和导入；万人并发在第三、四阶段专项实施 |

AI对抗验证作为补充，不替代确定性的测试用例和用户验收。

## 11. 第一阶段明确边界

第一阶段不建设：

- 微服务体系。
- 多租户隔离。
- 按国家拆分数据库schema。
- 通用无代码表单或DocType引擎。
- 完整事件总线平台。
- 企业微信正式身份接入。
- 移动端和MCP业务入口。
- 未经压测验证的高并发承诺。

## 12. 待技术设计冻结

- 后端、前端和数据库精确版本。
- 仓库结构与模块依赖检查方式。
- ORM、迁移工具和后台任务实现。
- Token或会话机制、密码策略和限流策略。
- 字段加密、密钥管理和敏感数据分级。
- 文件存储、病毒扫描和附件保留策略。
- 监控、日志、告警、备份和恢复产品。
- 8GB与32GB服务器的实际部署拓扑和容量参数。

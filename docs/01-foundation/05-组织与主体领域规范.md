# HRIS 第一阶段组织与主体领域规范

> 状态：`PARTIAL`  
> 版本：v0.1-draft  
> 日期：2026-07-31

## 1. 目标与范围

本规范定义第一阶段的法人、业务组织、虚拟组织、负责人、BP服务关系、成本中心和收入目标。

第一阶段需要解决：

- 维护单父业务组织树。
- 表达组织、法人和成本中心之间的多对多关系。
- 表达员工的主组织、兼岗、借调、项目和虚拟组织关系。
- 管理组织负责人和四类BP服务关系。
- 支持组织与关系的未来生效、历史查询和月度快照。

本规范不定义第二阶段的组织审批流，也不实现未来组织树预演。

## 2. 领域对象

| 对象 | 含义 |
|---|---|
| Legal Entity | 法人或其他需要独立维护的法律主体 |
| Organization | 业务组织树中的有效节点 |
| Organization Type | 可配置的组织类型 |
| Organization Relation | 兼岗、借调、项目、虚拟组织等非业务树关系 |
| Organization Leader | 组织负责人关系 |
| BP Service | BP人员对业务组织的服务关系 |
| Cost Center | 成本归集单元 |
| Organization Cost Allocation | 组织到成本中心的分摊关系 |
| Revenue Target | 叶子组织的年度/月度收入目标 |
| Organization Event | 新建、改名、换上级、合并、拆分、撤销等生效事件 |

## 3. 业务组织树

### 3.1 组织类型

默认组织类型：

- 集团
- BG
- BU
- 部门

管理员可以配置组织类型的编码、名称、启停状态和显示顺序。不限制某类组织只能挂在特定类型下面。

### 3.2 单父规则

- 每个有效业务组织在同一时点最多只有一个直接上级。
- 根组织没有上级。
- 不允许形成环。
- 不能把组织移动到自身或自身下级。
- 单父规则只适用于业务组织树，不约束虚拟、项目、兼岗、借调和BP关系。

### 3.3 组织编码

- 新组织编码为纯流水号。
- 编码由系统自动生成，创建后不得作为普通业务字段随意修改。
- 初始化导入保留历史组织编码。
- 自动编号必须避开已导入的历史编码。
- 编码位数、起始值和补零方式在编码规则中配置。

### 3.4 建议字段

| 字段 | 要求 |
|---|---|
| 组织编码 | 必填、唯一 |
| 组织名称 | 必填 |
| 组织类型 | 必填、引用有效类型 |
| 直接上级 | 根组织以外必填 |
| 所属国家/地区 | 按企业数据结构确定是否必填 |
| 状态 | 草稿、待生效、有效、失效 |
| 生效日期 | 必填 |
| 失效日期 | 可空 |
| 说明 | 可空 |
| 版本 | 用于并发控制和历史追踪 |

最终字段以组织数据表为准。

## 4. 组织生效事件

组织支持以下事件：

- 新建
- 改名
- 修改组织类型
- 换上级
- 合并
- 拆分
- 撤销或失效

规则：

- 每个事件必须填写生效日期。
- 未来生效事件在生效前不改变当前组织树。
- 当前产品只展示有效组织树。
- 待生效事件通过独立列表查询，不生成未来树。
- 生效时重新校验上级有效性、环路、有效期冲突和关联约束。
- 事件生效、失败、取消和回退均记录日志。
- 已生效事件如何回退，在事件技术设计中确定，但必须支持回退能力。

组织审批不在第一阶段作统一假设。后续流程引擎需要支持会签和或签。

## 5. 法人及主体关系

### 5.1 法人主数据

法人主体独立于组织维护。一个BU可以关联多个法人，一个法人也可以覆盖多个组织。

法人候选字段：

- 主体编码与名称。
- 国家或地区。
- 注册名称。
- 统一社会信用代码或当地注册标识。
- 注册地址。
- 状态和有效期。

具体字段等待现有主体表结构。

### 5.2 组织与法人

- 组织和法人是多对多关系。
- 关系记录生效日期、失效日期和历史版本。
- 组织树上下级关系不推导法人归属。
- 不因为上级组织关联某法人而自动把所有下级强制关联该法人。
- 人员四类主体不能仅由组织法人关系替代。

### 5.3 员工四类主体

每条有效雇佣在同一生效日期分别保存：

- 劳动合同主体。
- 发薪主体。
- 社保主体。
- 个税申报主体。

四者默认使用同一主体，但管理员可以分别调整。每一类在同一时点只能存在一个有效值。

## 6. 组织负责人

- 每个组织同一有效期间最多三名负责人。
- 三名负责人均为主负责人，不设置第一负责人、副负责人或主次排序。
- 负责人关系记录生效日期和失效日期。
- 同一人员可以负责多个组织。
- 负责人不自动获得全部敏感字段权限，数据权限另行授权。
- 后续审批可以按业务配置使用全部会签或任一或签。

组织详情同时展示当前负责人和历史负责人。

## 7. 虚拟组织与BP

### 7.1 组织关系类型

非业务树关系至少支持：

- 兼岗组织。
- 借调组织。
- 项目组织。
- 虚拟组织。
- 委员会。

关系类型可配置。每条关系记录人员、组织、关系类型、生效日期、失效日期和说明。

员工同一时间只有一个主组织，但可以同时存在多个其他类型的有效组织关系。

### 7.2 BP定义

| BP类型 | 含义 |
|---|---|
| HRBP | 人力伙伴 |
| EBP | 效率伙伴 |
| TBP | 目标伙伴 |
| FBP | 财务伙伴 |

规则：

- 同一个人在同一有效期间只能兼一种BP类型。
- 同一个BP可以服务多个业务组织。
- 一个业务组织可以由多个BP服务。
- BP服务关系不改变人员主组织、主职务或实线汇报关系。
- BP中心是否作为独立组织，由实际组织数据决定，不设系统强制。

## 8. 实线与虚线汇报

- 实线汇报表示主要业务管理关系。
- 虚线汇报表示兼岗、项目、专业或协同关系。
- 汇报关系独立于组织负责人和BP服务关系。
- 每条关系包含上级人员、下级人员、关系类型和有效期。
- 是否限制同时有效的实线上级数量，等待真实人员数据确认。

## 9. 成本中心

### 9.1 主数据

成本中心独立维护编码、名称、国家/地区、状态和有效期。多个组织可以归集到同一成本中心。

### 9.2 组织分摊

- 一个组织可以分摊至多个成本中心。
- 同一组织同一有效期间的有效比例合计必须为100%。
- 分摊比例使用统一精度，舍入后仍必须通过合计校验。
- 分摊方案记录生效日期、失效日期和版本。
- 未来版本生效前不改变当前方案。
- 第一阶段只实现组织级分摊。
- 数据模型保留未来员工级覆盖能力，但不提前实现。

第一阶段只保存和展示分摊关系，不执行薪酬或费用核算。

## 10. 收入目标

### 10.1 维护规则

- 只有叶子业务组织可以录入收入目标。
- 收入目标只有一个业务字段，不区分GMV、营收、利润等类型。
- 同时保存年度目标和拆解到每个月的月度目标。
- 每条目标必须选择币种。
- 调整目标时生成新版本并保留原版本。
- 月度快照保留当时有效目标。

### 10.2 汇总规则

- 上级组织的目标由当前有效下级目标自动向上汇总。
- 非叶子组织不直接维护汇总目标。
- 不同币种分别汇总和展示。
- 第一阶段不做汇率折算和集团币种合并。
- 第一阶段不管理实际收入，也不计算目标完成率。

年度目标与12个月月度目标是否必须相等，仍待确认。

## 11. 权限与审计

组织领域至少支持：

- 按组织和全部下级授权查看或维护范围。
- 按法人授权查看范围。
- 按BP服务范围授权，但第一阶段不默认开放BP角色。
- 将组织维护、负责人维护、成本分摊、目标维护和事件回退分为独立动作权限。
- 导入、导出和高风险操作独立授权。

所有变更记录对象、版本、修改前后值、操作者、时间、原因和来源。

## 12. 快照与查询

月初、月末快照至少保存：

- 当时有效的业务组织层级。
- 组织状态和组织类型。
- 组织与法人关系。
- 组织负责人和BP服务关系。
- 组织与成本中心分摊。
- 收入目标版本。

系统需要支持：

- 查询当前有效组织树。
- 查询指定组织的关系历史。
- 查询指定法人覆盖的组织和人员。
- 查询指定组织关联的法人、成本中心、负责人和BP。
- 对比两个快照时点的组织结果。

## 13. 异常规则

- 上级组织失效前，必须处理仍然有效的下级组织。
- 组织合并或拆分不自动改写人员和主体关系，必须通过明确事件处理。
- 负责人或BP人员失效时，系统提示受影响关系，不静默删除。
- 成本分摊不足或超过100%时不能使该版本生效。
- 叶子组织变为非叶子组织时，必须处理其直接维护的收入目标。
- 未来事件之间发生冲突时，后创建事件不能静默覆盖先创建事件。

## 14. 第一阶段验收要点

1. 可导入历史组织编码并继续自动编号。
2. 业务组织树满足单父、无环和未来生效。
3. 一个BU可关联多个法人，一个法人可关联多个组织。
4. 同一组织可按有效期在多个成本中心间100%分摊。
5. 组织可配置三名无主次负责人。
6. BP类型和服务范围符合唯一性规则。
7. 叶子组织目标按币种向上汇总并保留历史。
8. 当前树、历史版本、快照和审计结果一致。

## 1. 产品目标

为系统管理员和SSC提供从应聘到入职、再到在职变更和离职的统一管理工作台。所有关键变化通过版本化流程和人事事件落入第一阶段主数据，避免审批记录、人员结果和合同记录彼此割裂。

本PRD描述目标产品边界。标记为`PENDING_ENTERPRISE_INPUT`的页面行为不得直接生成最终开发任务。

## 2. 第二阶段用户

| 用户 | 产品目标 | 当前状态 |
|---|---|---|
| 系统管理员 | 配置流程、账号、权限并处理异常补偿 | `CONFIRMED / AVAILABLE` |
| SSC管理员 | 目标上管理应聘、发起人事事件、维护合同并跟踪流程 | `TARGET_CONFIRMED / ONBOARDING_INITIATE_ONLY` |
| HRBP | 按服务范围审批或查看流程 | `PENDING_ENTERPRISE_INPUT` |
| 业务负责人 | 按下级组织处理审批 | `PENDING_ENTERPRISE_INPUT` |
| 招聘人员 | 管理候选人、应聘和Offer | `PENDING_ROLE_SCOPE` |
| 员工本人 | 发起、撤回或查看本人流程 | `DEFERRED` |
| 审计角色 | 只读查看流程和审计 | `DEFERRED` |

## 3. 信息架构

目标一级导航：

```text
招聘与应聘
  ├─ 候选人
  ├─ 应聘记录
  └─ Offer确认
人员生命周期
  ├─ 入职
  ├─ 转正
  ├─ 调动
  ├─ 兼岗/借调
  ├─ 离职
  └─ 撤回/更正/回退
流程中心
  ├─ 我的待办
  ├─ 流程实例
  ├─ 流程配置
  └─ 异常补偿
合同与协议
  ├─ 合同/协议台账
  ├─ 到期提醒
  └─ 变更/续签/解除
```

当前工程 MVP 将上述能力收敛在“招聘需求”和“员工生命周期”工作区的多个页签内。信息架构迁移时只开放真实可用入口。

## 4. 页面与功能

### 4.1 生命周期工作台

用户可以：

- 按事件类型、状态、生效日期和人员查找人事事件。
- 查看待审批、待生效、已完成、失败和已回退记录。
- 进入流程实例、任务、选路历史和审计详情。
- 对有权限的失败任务重试或进入人工补偿。

页面必须明确区分“审批完成”和“业务已经生效”。未来事件审批完成后仍显示计划生效日期和待执行状态。

### 4.2 流程配置

系统管理员可以：

- 新建稳定流程代码和中文名称。
- 创建草稿版本，维护开始、审批、受控动作和结束节点。
- 为审批节点配置会签或或签。
- 配置角色、固定账号或受控表达式办理人及兜底角色。
- 通过结构化条件构建分支和默认路线。
- 预校验并发布新版本，查看历史版本。

不提供任意脚本编辑器。发布后版本只读；修改需要创建新版本。

### 4.3 待办与审批

办理人可以：

- 查看本人或授权代理范围内的待办。
- 查看本节点允许展示的申请字段和变更前后值。
- 通过或驳回并填写意见。
- 查看会签/或签进度，但不能替代其他办理人作决定。

任务权限、代理、转办、加签和超时策略等待企业流程确认。当前主管理员可以联调，不代表普通角色验收通过。

### 4.4 候选人与应聘

SSC或后续招聘角色可以：

- 创建候选人并维护最小联系方式。
- 关联第一阶段招聘需求并创建应聘记录。
- 更新筛选、面试、Offer、拒绝和撤回等阶段。
- 记录Offer信息并执行显式录用确认。
- 查看录用后创建的Person、Employment和主任职链接。

企业阶段名称、正式Offer字段和敏感字段权限待输入。当前联系方式和Offer使用通用JSON载荷，只允许合成数据，不录入真实电话、邮箱、Offer薪资或其他敏感值。

### 4.5 Offer确认与待入职转换

录用确认表单至少要求：

- 计划入职日期。
- 员工类型。
- 目标组织和职务（来自招聘需求，确认时可按权限调整）。
- 合同、发薪、社保、个税主体，默认一致并可分别调整。
- 新人主要证件，或明确选择已有Person进行复聘。
- 操作原因和幂等请求标识。

提交成功后显示Person、六位工号、待入职劳动关系和主任职。重复提交返回同一转换结果，不重复建档。

### 4.6 入职

已确认的产品边界：

- 入职页面只处理待入职转在职，不重复创建候选人、Person或劳动关系。
- SSC可以发起，系统管理员可以代发起并记录原因。
- 非`pending_start`记录不可发起。
- 同一劳动关系存在未结束入职事件时不可重复发起。

仍待确认后再进入页面开发：生效日期、审批节点、办理人、条件分支、驳回/撤回/超时和回退。

### 4.7 转正、调动、兼岗和借调

通用目标交互：

- 选择人员和有效劳动关系。
- 选择事件类型和生效日期。
- 展示当前关系，录入目标关系和变更原因。
- 提交前校验目标日期的组织、职务、法人和冲突关系。
- 审批完成后按生效日期执行；生效前不改变当前结果。
- 查看新旧关系和事件链。

各事件的字段、审批图和回退动作必须逐项确认，当前通用表单不视为企业最终页面。

### 4.8 离职、撤回和回退

离职目标交互：

- 展示劳动关系、主任职、兼岗/借调、合同和未来事件影响。
- 录入离职日期、原因和待处理项。
- 审批完成后按生效日期结束对应结果。
- 对已同步下游生成新的同步记录。

撤回待入职和回退已生效事件均创建新事件，不删除原记录。无法自动判断影响范围时转人工补偿。

### 4.9 合同与协议台账

用户可以：

- 按人员、合同编号、类型、状态和到期日期查询。
- 新建关联劳动关系或协议关系的记录。
- 查看版本、前后合同链和未来动作。
- 发起变更、续签、解除或取消，选择直接或审批模式。
- 查看到期提醒并处理状态刷新。

附件、电子签章和企业正式字段在输入包确认前显示为未开放，不使用自由JSON表单替代。

### 4.10 流程与审计详情

详情页需要在同一视图关联：

- 业务对象和当前结果。
- 流程定义及运行版本。
- 流程实例、当前节点和全部任务。
- 条件选路证据。
- 人事事件的计划值、执行值、状态和错误。
- 回退或补偿事件。
- 下游同步记录。
- 操作和敏感访问审计。

## 5. 关键状态模型

### 5.1 人事事件

```text
直接：ready → completed
审批：pending_approval → ready → completed
未来：ready → scheduled → completed
失败：ready/scheduled → failed → completed（安全重试）
驳回：pending_approval → rejected
回退：completed → 新建ROLLBACK事件 → completed
```

以上是当前API事实状态；原事件是否另行展示“已回退/已补偿”是待设计的查询投影，不能改写原事件。页面展示中文，企业流程不得直接跳过已确认前置状态。

### 5.2 流程实例与任务

```text
实例：running → completed / rejected / failed
任务：pending → completed / cancelled
```

会签要求同一节点全部有效任务通过；或签任一通过后取消其他待办。驳回策略可按流程配置前，默认结束实例并不改变业务结果。

### 5.3 应聘与录用

```text
active → screening → interview → offer
offer → 显式录用转换 → hired
任意业务阶段 → rejected / withdrawn
```

企业阶段可以调整，但`hired`必须由录用转换命令产生。

## 6. 关键验收旅程

### UAT-P2-01 新人录用转待入职

1. 使用合成候选人和招聘需求创建应聘。
2. 推进至Offer，填写计划入职日、目标组织/职务和四类主体。
3. 提供合成主要证件并确认录用。
4. 系统生成Person、六位工号、待入职Employment和主任职。
5. 使用同一幂等键重试，返回相同结果。

### UAT-P2-02 复聘

1. 选择已有离职Person。
2. 确认原主要证件在计划入职日有效。
3. 执行录用转换。
4. 系统复用原Person和工号，创建新的待入职劳动关系。

### UAT-P2-03 入职未来生效

该旅程等待`P2-Q001`生效日期规则确认后冻结。最低验收包括：重复发起拒绝、审批前不生效、到期只执行一次、审批晚于日期的处理和完整审计。

### UAT-P2-04 调动与回退

1. 对有效劳动关系发起未来调动。
2. 审批通过后，生效前仍显示原主任职。
3. 到达日期后结束原主任职并建立新主任职。
4. 按场景发起回退，形成新事件并恢复正确关系。
5. 原调动、回退和审计均保留。

### UAT-P2-05 会签、或签与条件路由

1. 发布包含条件线和默认线的合成流程。
2. 分别运行会签和或签节点。
3. 核对任务状态、实际办理人和选路历史。
4. 构造多条件同时命中，系统应失败而非任意选路。

### UAT-P2-06 合同生命周期

1. 建立合成合同。
2. 依次验证变更、未来续签、到期提醒和解除。
3. 回退一次未来或已执行动作。
4. 核对版本、前后合同链、状态和事件审计。

## 7. 页面通用要求

- 默认使用中文业务名称，稳定代码在详情或高级区域显示。
- 未实现或无权限模块不显示假入口。
- 表单在提交前展示目标生效日期和关键变更摘要。
- 高风险操作要求二次确认、原因和明确后果。
- 错误信息包含业务含义和Trace ID，不显示堆栈或秘密。
- 桌面端为本阶段主要入口；移动尺寸可访问不等于移动门户交付。

## 8. 完成与发布边界

当前管理端可以由主管理员演示流程、应聘、录用、人事事件和合同通用链路；`SSC_ADMIN`目前只能发起入职事件，尚不能访问完整生命周期工作区。整体状态为`IMPLEMENTED_GENERIC`。以下条件完成前，产品不得标记第二阶段企业验收通过：

- 全部核心人事流程图及办理人规则确认。
- SSC和普通办理人权限UAT完成。
- 合同/协议正式字段和附件边界确认。
- 企业异常、撤回、超时、回退和下游同步场景通过。
- 第二阶段Review签字完成。

当前输入只处理入职流程，详见[第二阶段需求规格第13节](./12-第二阶段需求规格.md)和[企业输入包06](../input-packs/06-hr-workflow-input.md)。

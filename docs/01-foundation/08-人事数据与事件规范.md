# HRIS 第一阶段人事数据与事件规范

> 状态：`PARTIAL`  
> 版本：v0.1-draft  
> 日期：2026-07-31

## 1. 目标

本规范定义当前人员结果、带有效期的历史、业务事件、回退、快照和审计之间的关系。

目标是：

- 日常页面可以快速读取当前有效结果。
- 未来生效变更不会提前污染当前数据。
- 任一重要变化都能解释由谁、何时、因何产生。
- 可以查询指定时点的人员状态。
- 错误操作可以按权限回退且完整留痕。
- 第二阶段流程引擎可以驱动同一套人员结果，而不重建主数据。

## 2. 分层模型

```text
流程或管理员操作
        │
        ▼
业务事件 / 更正记录
        │ 到达生效条件
        ▼
当前有效结果 + 有效期历史
        │
        ├─ 月初/月末快照
        ├─ 领域变更通知
        └─ 操作审计
```

各层职责：

| 层次 | 职责 |
|---|---|
| 当前结果 | 支撑日常列表、详情和统计 |
| 有效期历史 | 记录每段时间内的有效业务状态 |
| 业务事件 | 表达变化原因、生效日期、审批或执行状态 |
| 快照 | 固化特定时点的完整结果 |
| 审计 | 记录系统和人员执行过的操作 |

审计日志不能替代业务历史，快照也不能替代事件。

## 3. 事件范围

### 3.1 第一阶段需要承载

- 组织新建、改名、换上级、合并、拆分和撤销。
- 组织负责人和BP关系变化。
- 成本中心分摊版本变化。
- 收入目标调整。
- 人员基础档案更正。
- 雇佣当前结果更正。
- 员工组织、职务、汇报和四类主体的未来生效变更。
- 事件取消和回退。

第一阶段不要求为以上所有事件建设审批流，但数据模型必须保留发起、审批和来源标识。

### 3.2 第二阶段扩展

- 入职。
- 转正。
- 调岗。
- 兼岗。
- 借调。
- 离职。
- 合同与协议变化。
- 流程撤回、驳回和重新提交。

第二阶段流程完成后，以流程产生的事件为人员结果的权威来源。

## 4. 通用事件字段

事件至少包含：

- 事件编号。
- 事件类型。
- 业务对象类型和标识。
- 发起人、发起时间和来源。
- 生效日期。
- 当前状态。
- 变更原因。
- 变更前结果。
- 计划变更后结果。
- 实际执行结果。
- 字段差异。
- 关联流程编号。
- 关联原事件或回退事件。
- 执行次数、最后错误和执行时间。
- 并发版本。

快照结构可以按领域实现，但必须能够明确还原关键字段差异。

## 5. 事件状态

第一阶段基础状态建议为：

```text
草稿 → 待生效 → 已生效
  ├→ 已取消
  └→ 执行失败

已生效 → 回退处理中 → 已回退
                      └→ 回退失败
```

若事件需要审批，可在第二阶段扩展：

```text
草稿 → 审批中 → 已通过待生效 → 已生效
          ├→ 已驳回
          └→ 已撤回
```

具体事件可裁剪不适用状态，但状态代码、转换条件和权限必须明确。

## 6. 生效规则

- 事件必须有明确生效日期。
- 即时事件通过同一事务提交事件和当前结果。
- 未来事件在生效日前只显示为待生效。
- 生效时重新校验业务规则，不能只相信发起时校验。
- 生效任务必须支持幂等和安全重试。
- 事件失败不得留下部分更新结果。
- 同一对象多个未来事件发生冲突时，不允许静默覆盖。
- 对当前结果的更新需要并发控制。
- 生效后记录实际差异、执行时间和执行版本。

界面只展示当前有效组织树和人员结果；组织未来事件在对应组织详情中按生效日期查看，不建设独立的待生效组织事件页面。

## 7. 当前结果与历史

### 7.1 当前结果

当前结果包括但不限于：

- 当前雇佣状态。
- 当前主组织和主职务。
- 当前其他组织关系。
- 当前实线和虚线汇报。
- 当前四类主体。
- 当前组织负责人和BP关系。

当前结果可以存储为主表字段、有效关系表或可重建投影，具体方式由数据模型设计决定。

### 7.2 时点查询

系统需要支持：

- 查询当前状态。
- 查询全部历史事件。
- 查询字段变更时间线。
- 查询指定日期的组织、职务、主体和状态。
- 对比两个时间点的差异。
- 从月度快照进入明细复核。

时点查询结果必须标明数据来源和有效期，避免把快照、实时重建和当前结果混为一谈。

## 8. 修改、更正与流程结果

- 基础档案可以由授权SSC按生效日期维护结果。
- 每次修改均记录前后内容。
- 系统界面引导核心人事关系使用更正事件。
- 第一阶段不强制所有信息修改都经过流程。
- 第二阶段存在人事流程时，以已完成流程生成的事件为准。
- 流程处理中不得通过普通编辑无痕改变同一字段。
- 紧急更正需要独立权限、原因和审计。

## 9. 回退

事件必须支持回退，每次回退保留完整操作日志。

回退要求：

- 回退前校验当前结果是否仍由目标事件产生。
- 已被后续事件覆盖时，不能直接把旧值强行覆盖当前结果。
- 回退必须记录目标事件、原因、操作者和影响范围。
- 回退失败不能产生部分状态。
- 回退后仍保留原事件和原审计。
- 已同步下游时，回退生成新的业务记录和出站同步记录，关联原记录后再次同步，不修改原同步历史。
- 回退属于高风险独立权限。

回退执行方式由事件类型和场景策略确定：

- 直接生效：授权用户提交后立即执行回退。
- 审批生效：通过回退审批后执行；驳回或撤回不改变当前结果。
- 回退审批是受控领域动作，第二阶段可由通用流程引擎接管。
- 未注册回退策略或影响范围无法确定时默认拒绝自动回退。

回退策略支持以下方式并按事件类型组合：

- 从历史版本或快照生成新的恢复结果。
- 创建补偿事件并生成新的结果版本。
- 组合使用恢复结果和补偿事件。

无论采用哪种方式，都必须生成新记录，满足可追溯、可重试且不破坏后续历史；存在后续事件时必须先校验事件链，不能直接覆盖。

## 10. 月初月末快照

### 10.1 快照时点

- 系统自动生成月初快照和月末快照。
- 月份边界按照快照策略配置的时区计算，不使用服务器本地时区隐式判断。
- 每个快照批次保存所用时区、边界时刻和规则版本。
- 授权管理员可以补跑或生成修订版本。

### 10.2 快照内容

至少包含：

- 组织和层级。
- 组织与法人、成本中心关系。
- 收入目标。
- 月度编制和人数结果。
- Person与Employment关键状态。
- 员工组织、职务、主体和汇报关系。
- 使用的规则版本。

### 10.3 版本

- 快照不可由普通用户直接修改。
- 错误数据先更正业务数据，再创建快照修订版本。
- 修订不覆盖原快照。
- 每个版本记录原因、生成批次、操作者和统计范围。
- 快照任务可重试且幂等。

月结后按以下流程修订：

1. 保留原始月初、月末快照并保持只读。
2. 更正源业务数据。
3. 授权用户生成与原快照关联的修订版本。
4. 记录原因、操作者、差异和版本关系。
5. 复核后重新冻结修订版本。

## 11. 领域联动

第一阶段只实现明确且必要的同步联动：

| 变化 | 必要结果 |
|---|---|
| 待入职日期或人员类型变化 | 更新适用月份人员统计 |
| 主组织或职务生效 | 更新当前归属和后续统计 |
| 离职或入职撤回生效 | 按生效日期释放相关人数 |
| 法人主体变化 | 更新人员主体结果 |
| 组织换上级生效 | 更新当前组织树，不改写历史快照 |
| 占编规则变化 | 记录规则版本，影响生效日期后的统计 |

系统内部联动应通过明确应用服务或可靠消息记录实现。第一阶段不建设通用事件总线平台。

## 12. 下游集成预留

企业微信、自建OA和其他下游系统已有API，但接口清单和数据主从关系尚未提供。

第一阶段需要预留：

- 稳定业务对象标识。
- 版本化API。
- 变更事件编号。
- 幂等键。
- 同步状态和错误记录。
- 可重试的出站消息表或等效机制。

在接口资料确认前，不实现猜测性的字段映射和自动同步。

## 13. 权限与审计

独立权限至少包括：

- 创建和修改草稿事件。
- 取消待生效事件。
- 紧急更正。
- 回退已生效事件。
- 补跑或修订快照。
- 查看事件前后值。
- 查看敏感字段差异。

审计至少记录：

- 事件创建、提交、审批、执行、取消和回退。
- 自动任务及重试。
- 当前结果的直接更正。
- 快照生成和修订。
- 下游初始同步、回退新记录的再次同步及失败补偿。

## 14. 异常与补偿

- 生效时引用对象无效：事件失败并给出业务错误，不部分执行。
- 当前版本已变化：标记并发冲突，要求重新确认。
- 多事件有效期冲突：阻止后一个事件生效。
- 自动任务中断：使用幂等键重试。
- 下游同步失败：本地业务事务不回滚；按新记录的幂等键重试，仍失败时进入人工补偿。
- 快照部分失败：整批不发布为成功版本。
- 回退影响范围无法确定：禁止自动回退，转人工处理。

## 15. 第一阶段验收要点

1. 未来事件在生效前不改变当前结果。
2. 到达生效日期后结果只应用一次，失败可安全重试。
3. 可查看事件前后值、字段差异和完整操作记录。
4. 可查询指定时点的关键人员关系。
5. 已生效事件具备受控回退能力，原历史不被删除。
6. 月初月末快照可复核、补跑和修订。
7. 事件、当前结果、快照和审计之间可以相互关联。

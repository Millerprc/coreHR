## 1. 多数据库兼容

第五阶段在当前PostgreSQL基线之外增加以下数据库支持：

- MySQL。
- Oracle Database。

第一至第四阶段仍只以PostgreSQL作为开发、测试和生产数据库基线，不要求MinimaxCode提前：

- 建设多数据库抽象层。
- 为MySQL或Oracle编写迁移。
- 建立多数据库测试矩阵。
- 回避所有PostgreSQL能力而采用最低公共特性集。
- 引入与当前交付无关的数据库适配框架。

第五阶段启动前单独确认：

1. PostgreSQL、MySQL和Oracle的支持版本范围。
2. 是同一套部署支持三种数据库，还是按客户版本形成不同发行包。
3. SQLAlchemy方言、驱动、连接池和迁移工具方案。
4. 标识列、序列、日期时间、JSON、索引、约束、分页、锁和批量写入差异。
5. 现有PostgreSQL数据向MySQL或Oracle迁移的范围和工具。
6. 每种数据库的单元、集成、迁移、性能和备份恢复测试矩阵。
7. Oracle许可、驱动分发、部署运维和国产化环境要求。

具体兼容边界、实施顺序和验收标准由用户在第五阶段另行确认。

## 2. 企业级中间件

Apusic、独立API网关、消息总线和ESB等企业级应用服务器或集成中间件继续保留在第五阶段评估，不影响第一至第四阶段当前架构。

多数据库兼容与企业级中间件是两个独立议题，不因选择Apusic而默认必须选择Oracle，也不因支持Oracle而默认必须引入Apusic。

## 1. 产品目标

为系统管理员和SSC提供统一的考勤管理工作台，从规则、班次、排班和原始打卡生成可解释的日报、月报和假期余额结果，并通过版本和冻结机制保证历史可复核。

本阶段首先服务管理员，不建设员工移动门户。企业规则确认前，页面显示的计算结果只用于工程UAT。

## 2. 第三阶段用户

| 用户 | 产品目标 | 当前状态 |
|---|---|---|
| 系统管理员 | 配置权限、规则、异常补偿并处理冻结 | `CONFIRMED / AVAILABLE` |
| SSC/考勤管理员 | 目标上维护规则、班次、排班、假勤、余额并复核报表 | `TARGET_CONFIRMED / NOT_YET_AUTHORIZED` |
| HRBP | 查看服务组织考勤与异常 | `PENDING_ROLE_SCOPE` |
| 业务负责人 | 查看全部下级并处理相关审批 | `PENDING_ROLE_SCOPE` |
| 员工本人 | 打卡、请假、销假和查询本人结果 | `DEFERRED` |
| 审计角色 | 查看冻结、修订和敏感访问日志 | `DEFERRED` |

## 3. 信息架构

目标一级导航：

```text
考勤管理
  ├─ 考勤日报
  ├─ 考勤月报
  ├─ 异常处理
  ├─ 排班
  ├─ 原始打卡
  ├─ 请假与销假
  ├─ 假期余额
  ├─ 期间冻结
  └─ 规则与班次
```

当前工程 MVP 在“考勤管理”中提供六个页签：日报与月报、排班与打卡、请假与销假、假期余额、期间冻结、规则与班次。后续导航拆分不得提前显示未实现入口。

## 4. 页面与功能

### 4.1 考勤总览

目标展示：

- 当前月份、规则时区和月结状态。
- 已排班人数、待计算日报、异常人数和待复核月报。
- 请假待办、余额异常和即将失效额度。
- 最近补传打卡、解冻和重算操作。

指标口径未确认前不显示误导性总数。

### 4.2 规则与班次

考勤管理员可以：

- 创建规则集和草稿版本。
- 选择IANA时区和生效日期。
- 查看规则适用范围和命中优先级。
- 维护班次上下班、跨午夜、休息和取卡窗口。
- 预校验并发布版本，查看历史。

当前页面已支持规则版本和基础班次。适用范围、工作日历和精细计算矩阵在企业输入后扩展。

### 4.3 排班

用户可以：

- 按人员、组织、日期和班次查询。
- 为一个或多个有效劳动关系安排班次。
- 调整或取消排班，保留来源和历史。
- 查看班次跨日、规则版本和冲突提示。

批量周期排班、同日多班次和换班流程等待企业样例，不在当前表单中假设。

### 4.4 原始打卡

用户可以：

- 按人员、日期、来源和记录ID查询原始打卡。
- 通过受控接口或管理员入口接收带时区打卡。
- 查看进/出类型、来源、原时间和证据摘要。
- 识别重复来源记录并返回原记录。

原始打卡不提供删除按钮。补卡和纠错目标上必须形成新证据或受控记录，但当前正式补卡/纠错闭环尚未实现。`raw_payload`字段合同完成前只使用合成数据。

### 4.5 请假与销假

用户可以：

- 查看假期类型、余额模式和当前余额。
- 创建请假，选择日期/数量并填写原因。
- 关联第二阶段流程实例。
- 批准、驳回、取消或创建销假记录。
- 查看批准扣减和销假冲回流水。

半天、小时假、跨班次、重叠和审批前预占等待企业规则确认。

### 4.6 假期余额

用户可以：

- 按人员、假类和年度查看账户。
- 查看当前余额、版本和全部不可变流水。
- 人工发放、调整、结转或计提，填写生效日期和原因。
- 识别重复幂等请求和余额不足。

自动计提配置需要明确频率、工龄、折算、封顶、清零和结转，不使用自由文本公式。

### 4.7 考勤日报

用户可以：

- 按人员、组织、日期、状态和异常码查询。
- 查看排班、计划/实到分钟、迟到/早退、缺卡、假勤和证据。
- 查看所用规则版本、原始打卡和请假记录。
- 在未冻结期间填写原因后重算，生成新版本。
- 对比历史版本和当前版本。

当前通用算法只用于工程验证，页面需要明确显示“企业规则未完成UAT”提示。

### 4.8 考勤月报

用户可以：

- 按自然月、人员、组织和状态查询。
- 查看计划、出勤、请假、缺勤、迟到和早退汇总。
- 下钻到当前日报版本和异常证据。
- 在未冻结期间重算并查看版本。
- 导出经授权的复核数据。

月报不展示工资扣款或薪酬金额。

### 4.9 期间冻结

考勤管理员可以：

- 创建覆盖完整自然月的月结冻结。
- 创建任意日期段的特殊业务冻结。
- 查看冻结范围、原因、操作者和状态。
- 填写原因后解冻，完成更正和重算后重新冻结。

冻结期间：

- 禁止生成新的日报/月报版本。
- 继续接收原始打卡证据。
- 已冻结结果和原版本永久保留。

### 4.10 异常处理

目标异常工作台集中展示：

- 无排班、有排班无打卡、单侧打卡和多次卡。
- 请假与打卡冲突、余额不足和跨年申请。
- 计算失败、规则缺失和补传后待重算。
- 冻结期新增证据和待解冻事项。

当前没有独立异常工作台；相关信息分布在日报、打卡和假勤页面，属于后续企业适配任务。

## 5. 状态与版本模型

### 5.1 规则

```text
draft → published/active → superseded/inactive
```

已发布版本不覆盖。新版本按生效日期参与后续计算，冻结历史默认不重算。

### 5.2 排班

```text
active → cancelled
```

调整排班应保留原来源和审计；正式版本化策略等待排班样例确认。

### 5.3 请假与销假

```text
draft → approved / rejected / cancelled
approved → cancellation request → cancelled（余额冲回）
```

企业审批图确认后，状态推进以第二阶段流程为准。当前假期类型只有规则字段，没有独立规则版本和生效日期；正式规则确认后必须补齐，不能通过原地改JSON作为历史版本。

### 5.4 日报/月报

```text
version 1(current)
  → 重算成功
version 1(history) + version 2(current)
```

冻结只阻止新版本，不删除旧版本或原始证据。

### 5.5 冻结

```text
active → released
重新冻结创建新的active记录
```

解冻记录不可恢复成active；复核完成后新建冻结记录，以保留完整操作链。

## 6. 关键验收旅程

### UAT-P3-01 正常班与跨午夜

1. 发布带时区的合成规则和普通班次。
2. 排班并接收进、出打卡。
3. 生成日报，核对计划、实到、状态和证据。
4. 对跨午夜班次重复，确认日期归属和时区正确。

企业取卡窗口确认前，本旅程只能验证基础技术链路。

### UAT-P3-02 重复和缺失打卡

1. 两次提交同一来源记录，系统只保留一条。
2. 构造无卡、缺入卡、缺出卡、多次卡和无类型卡。
3. 生成日报并与企业验收矩阵逐项对照。

### UAT-P3-03 请假、余额和销假

1. 建立跟踪且余额不足阻断的合成假类。
2. 发放额度并批准一笔请假，余额产生扣减流水。
3. 重复批准不重复扣减。
4. 批准销假或取消，产生反向流水并恢复余额。

### UAT-P3-04 日报到月报

1. 为一个月创建多日排班、打卡和已批准请假。
2. 生成/补算日报并聚合月报。
3. 下钻核对月报只引用当前日报版本。
4. 更正一天后重算日报和月报，旧版本仍可查。

### UAT-P3-05 月结冻结

1. 对完整自然月创建冻结。
2. 尝试重算日报/月报，应被拒绝。
3. 新增补传打卡，应成功保存原始证据但不改结果。
4. 填写原因解冻、重算并重新冻结。
5. 核对冻结、解冻、结果版本和审计链。

### UAT-P3-06 企业规则对账

使用[考勤规则输入包](../input-packs/07-attendance-rule-input.md)中的合成案例，覆盖正常、迟到、早退、缺卡、缺勤、跨午夜、半天/小时假、销假和节假日。所有案例逐字段符合期望后，才能批准日报/月报进入第四阶段薪酬接口设计。

## 7. 页面通用要求

- 所有日期和时间明确显示规则时区，跨午夜场景同时显示业务日期。
- 结果页面必须能下钻到规则、排班、原始打卡和假勤证据。
- 重算、余额调整、冻结和解冻必须填写原因并二次确认。
- 列表支持组织、人员、日期、状态和异常过滤；敏感列按权限展示。
- 大批量操作必须异步展示进度、成功数、失败数和错误明细。
- 移动尺寸访问不等于员工移动打卡门户交付。

## 8. 完成与发布边界

当前管理端六个页签和通用计算链路由主管理员通过`ATTENDANCE_ADMIN`能力演示；`SSC_ADMIN`尚未获得考勤管理权限。整体状态为`IMPLEMENTED_GENERIC`。以下条件完成前，产品不得标记第三阶段企业验收通过：

- 企业规则范围、班次、异常、假期和月结规则确认。
- 规则案例逐项通过。
- 请假/销假审批与普通角色权限完成。
- 正式打卡接口完成联调。
- 日报/月报业务对账签字完成。
- 容量、备份和安全专项按上线范围验证。

当前仍先处理第二阶段入职流程；第三阶段输入顺序见[第三阶段需求规格第16节](./14-第三阶段需求规格.md)。

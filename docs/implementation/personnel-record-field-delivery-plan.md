# 第一阶段人员档案字段实施计划

> 状态：`IMPLEMENTED / READY_FOR_USER_REVIEW`
> 日期：2026-08-12
> 依据：[人员档案领域规范](../01-foundation/07-人员档案领域规范.md)、[人员字段验收包](../input-packs/05-personnel-record-field-acceptance.md)、[EHR装配方案](../migration/ehr-corehr-assembly-plan.md)
> 数据边界：本计划只使用结构和合成数据；安全闸门通过前禁止导入真实证件、联系方式和地址

## 1. 当前事实

现有系统已经支持 Person、Employment、EmploymentAssignment、AgreementRelationship、六位工号、人员档案聚合页面、通用审计，以及本计划新增的人员敏感字段安全底座。

截至2026-08-12，本轮已完成：

- Person法定姓名及已确认基础字段。
- 四类法人主体的独立有效日期关系和历史查看。
- 证件、联系方式、地址、紧急联系人、教育、工作和家庭成员子实体。
- 应用级AES-256-GCM加密、HMAC精确摘要、默认脱敏、明文查看权限与专项审计。
- 主管理员页面及Person非敏感基础层导入导出。

完整企业迁移仍未完成：敏感批量导入、Employment/Assignment/Reporting/Agreement/Label分层迁移、正式企业字段表头、脱敏样例UAT及业务签字仍在本轮边界之外。因此“安全可操作的人员档案工程能力”与“真实全量人员数据已完成迁移”必须继续区分。

## 3. 原子任务与交付物

### PER-001 冻结字段合同

**状态：`COMPLETE`（2026-08-12全部采用推荐值）**

**输入**

- [55字段验收模板](../input-packs/templates/03-personnel-field-acceptance.csv)。
- 用户确认8项推荐规则及企业例外。

**交付物**

- 字段代码、类型、必填时点、唯一性、敏感级别、修改方式和历史方式的Accepted版本。
- 旧 EHR 字段到目标字段的结构对照；不含真实值。

**验收**

- 每个第一阶段字段只有一个目标实体和一个正式语义。
- 民族、国籍、所在国家/地区不混用。

### PER-002 批准敏感字段安全ADR

**状态：`COMPLETE`（[ADR-0004](../adr/ADR-0004-personnel-sensitive-field-protection.md) Accepted）**

**推荐提案**

- 证件号码、个人联系方式、详细地址等由应用层使用认证加密保存。
- 每个密文保存密钥版本、随机 nonce 和认证标签；解密失败必须拒绝，不返回空值兜底。
- 精确去重与检索使用独立密钥生成不可逆 HMAC 摘要，不用可暴力枚举的普通 SHA 摘要。
- 页面和普通 API 只返回脱敏值；明文使用单独动作、原因和权限，并写敏感访问审计。
- MVP 的密钥由部署环境注入且禁止写入仓库/数据库；接口预留外部 KMS/密钥托管，生产启用前必须确认托管、轮换、备份和恢复责任。

**备选方案**

- 只做磁盘或数据库透明加密：无法阻止应用查询、导出和日志泄露，不采用。
- PostgreSQL 内直接解密：密钥边界、权限和轮换更难治理，不作为默认方案。
- 首版接入独立数据保险库：隔离最好，但当前部署和运维成本过高，保留为未来复审项。

**闸门**

- 该方案属于架构决策，必须经用户明确批准后才写ADR和实现。

### PER-003 加密、脱敏和检索底座

**状态：`COMPLETE`**

**所有权**

- `apps/api/src/hris/core/`安全组件、配置和单元测试。

**交付物**

- 版本化认证加密值对象。
- HMAC检索摘要和统一规范化器。
- 电话、邮箱、证件和地址脱敏器。
- 密钥缺失、错误版本、认证失败、轮换中的失败关闭策略。

**验收**

- 同一明文重复加密产生不同密文；规范化后摘要稳定。
- 日志、异常、审计通用前后值和测试快照不出现明文。
- 密钥未配置时敏感写入和明文读取拒绝启动或拒绝请求。

### PER-004 字段权限与敏感访问审计

**状态：`COMPLETE`（主管理员范围）**

**交付物**

- `PERSON_VIEW`、`PERSON_EDIT_BASIC`、`PERSON_SENSITIVE_VIEW`、`PERSON_SENSITIVE_REVEAL`、`PERSON_IMPORT`、`PERSON_EXPORT`权限。
- 字段策略服务；主管理员通配权限继续兼容。
- 明文读取命令要求原因，保存操作者、Person、字段类别、时间和Trace ID，不保存明文。

**验收**

- 没有Reveal权限只能得到脱敏值。
- 普通人员查看权限不能通过列表、详情、搜索、导出或错误旁路取得明文。

### PER-005 密钥运行手册

**状态：`COMPLETE`**

**交付物**

- 本机、测试、生产三套密钥来源约束。
- 生成、注入、轮换、回滚、备份恢复和离职交接步骤。
- 不输出密钥的只读健康检查。

**验收**

- 旧密钥保留期间可解密旧记录；批次轮换后使用新版本写入。
- 丢失密钥的恢复边界被明确记录，禁止用空值或重置密钥伪造恢复。

### PER-006 Person基础字段

**状态：`COMPLETE`**

**交付物**

- 法定姓名、民族、婚姻、政治面貌等已确认字段的迁移、Schema、服务和页面。
- 展示姓名默认规则和更正审计。

**验收**

- 现有 Person ID、工号和历史关系不变。
- 建档允许推荐的可空字段缺失，但产生可查询的数据质量项。

### PER-007 四类主体有效日期关系

**状态：`COMPLETE`**

**交付物**

- Employment与法人主体的独立关系表：合同、发薪、社保、个税四种类型。
- 同类同一日期唯一、默认复制合同主体、允许分别调整。
- 现有 Employment 四列保留为当前投影并完成历史数据回填。

**验收**

- 任意查看日期可取得四类结果；新版本自动闭合前一版本。
- 人事事件、档案页面和人数统计继续引用同一Employment稳定身份。

### PER-008 非敏感初始化契约

**状态：`PARTIAL`（Person基础层完成，其余关系层待后续迁移任务）**

**范围**

- Person基础字段、Employment、Assignment、Reporting、Agreement和Label，不含任何受保护明文。

**交付物**

- 模板、预校验、来源追踪、整批事务模式和拒绝报告。
- 重复Person只形成候选，不自动合并。

### PER-009 证件

**状态：`COMPLETE`（建档、列表、脱敏、Reveal与审计）**

**交付物**

- 一对多证件、主要证件唯一、国家/地区与有效期、验证状态。
- 加密号码、脱敏值和不可逆检索摘要。
- 二次入职匹配候选，不在不确定时自动合并。

### PER-010 联系方式和地址

**状态：`COMPLETE`（建档、列表、脱敏、Reveal与审计）**

**交付物**

- 一对多联系方式、主要标记、有效期和规范化检索。
- 常住/通讯地址及受保护详细地址。
- 重复联系方式作为质量提示，不默认当作同一自然人证据。

### PER-011 紧急联系人及关联档案

**状态：`COMPLETE`（附件按原边界延后）**

**交付物**

- 紧急联系人、教育经历、工作经历和家庭成员独立实体。
- 第一阶段全部可选；敏感字段执行同一保护策略。
- 附件只保留接口位置，安全附件底座未完成前不接收文件。

### PER-012 主管理员人员档案页面

**状态：`COMPLETE`（第一批主管理员范围）**

**交付物**

- 概览、身份、证件、联系方式、地址、紧急联系人、雇佣、任职/汇报、协议和历史页签。
- 默认脱敏、Reveal二次动作、原因输入和过期后清除明文状态。
- 使用现有Ant Design页面壳；参考`tmp/ui-mockup/06-nav-system.html`的信息架构，不复制静态CSS。

### PER-013 分层导入

**状态：`PARTIAL`（Person非敏感基础层完成；敏感层明确禁止进入通用暂存JSON）**

**执行顺序**

1. Person非敏感首记录。
2. Employment及四类主体。
3. 主任职、其他任职和汇报。
4. 协议与标签。
5. 经安全闸门批准后，单独导入证件、联系方式、地址和紧急联系人。

**验收**

- 敏感和非敏感批次不能混用模板。
- 敏感导入错误只返回行号和错误代码，不回显源值。

### PER-014 EHR映射与脱敏样例UAT

**状态：`HOLD`（等待脱敏样例和用户批准）**

**输入**

- 旧表字段结构、枚举对照和本机生成的合成/脱敏样例。

**交付物**

- 映射版本、转换报告、重复候选、拒绝清单和对账汇总。
- 不把旧认证、银行、薪酬、附件或未确认字段混入本批。

### PER-015 完整验收

**状态：`PARTIAL`（自动化工程验收通过；业务UAT、全量迁移与容量验证未完成）**

**自动化证据**

- 数据库迁移、回退和模型差异检查。
- 权限矩阵、加密、篡改、密钥版本、脱敏、搜索、导出和日志泄漏测试。
- Person/Employment/Assignment/Reporting有效期与并发测试。
- 管理端页面、敏感Reveal和导入失败路径测试。

**业务证据**

- 使用合成数据完成一次待入职、在职、离职、二次入职和协议并存Review。
- 用户批准后，才制定真实人员数据迁移窗口和回滚方案。

## 5. MinimaxCode任务卡规则

如果后续交由MinimaxCode并行开发，每次只下发一个`PER-xxx`任务，必须附：

- 明确文件所有权和禁止改动范围。
- 输入/输出Schema及错误代码。
- 正常、边界、失败、权限和敏感泄漏测试。
- 迁移升级/回退与既有数据兼容证据。
- 交付回执、命令结果和未完成边界。

不得把PER-003、PER-004、PER-009或敏感导入拆给互不知情的并行任务，以免加密、权限和字段模型出现不一致。

# coreHR Ant Design页面与交互载体规范

> 状态：`ACTIVE`  
> 版本：v1.1  
> 日期：2026-08-19  
> 决策依据：D-068、D-069、D-070、D-087  
> 适用范围：coreHR全部Web前端页面、原型、功能需求、开发任务和验收

## 1. 目的与权威边界

本规范把“遵循最新Ant Design”和“页面只能使用弹窗类容器或新浏览器标签页”的产品决策转成可执行规则。

- 本规范约束页面结构、组件选择、交互载体、导航、安全和验收。
- 视觉品牌方向、业务字段、业务流程和权限规则仍需在对应功能需求中批准。
- [Design System v1候选稿](./design-system-v1.md)中的方向A/B尚未批准，只作为Token和视觉方向输入；与本规范冲突时以本规范为准。

## 2. Ant Design版本策略

- 设计与交互评审持续对照[Ant Design官方当前稳定文档](https://ant.design/)。截至2026-08-19，官网组件文档显示`6.6.1`。
- 当前仓库`apps/web/package.json`锁定`antd 6.5.2`。生产代码只能使用该版本已经支持的API，不得因“遵循最新规范”而静默升级依赖。
- Ant Design升级必须单独建立任务，记录版本差异，并通过TypeScript检查、生产构建、组件测试、视觉检查、可访问性检查和关键E2E旅程。
- 设计原则采用官方的[Natural、Certain、Meaningful、Growing](https://ant.design/docs/spec/values/)；布局、层级和组件用法以官方稳定文档为准。

## 3. 宿主页与允许的交互载体

列表、组织树、仪表盘和工作台是当前浏览器标签页中的“宿主页”。宿主页负责检索、筛选、批量操作和发起任务，用户完成子任务后应能继续使用原有上下文。

从宿主页发起的新增、编辑、详情、流程和子任务，只允许以下三种载体：

| 载体 | 适用内容 | 默认边界 | 不适用内容 |
|---|---|---|---|
| `MODAL` | 确认、简短说明、轻量表单、单一决策 | 通常不超过6个简单字段；无页内标签和多步骤 | 长表单、复杂详情、历史对比、需要并行参照 |
| `DRAWER` | 保留宿主页上下文的预览、新增或编辑 | 通常7至20个字段、不超过3个信息分组；单一任务 | 多步骤流程、密集页内标签、跨对象复杂操作 |
| `NEW_TAB` | 完整详情、长表单、历史/审计、复杂流程、打印导出 | 超过20个字段、超过3个分组，或存在页内标签、多步骤和并行参照 | 一次确认、极短编辑 |

字段和分组数量是默认判断线，不是业务规则。如果功能需求选择不同载体，必须写清原因并由产品决策人批准。

## 4. 强制导航规则

1. 二级业务页面不得在当前标签页替换宿主页。
2. `MODAL`和`DRAWER`统称“弹窗类容器”，都必须保留当前宿主页状态。
3. 禁止嵌套两层业务Modal/Drawer；第二层复杂任务转为`NEW_TAB`。弹窗内的简短危险操作确认不视为第二个业务页面。
4. `NEW_TAB`必须使用稳定、可刷新、可直接授权校验的URL。页面状态来自URL和服务端，不依赖`window.opener`或仅存在于原页面内存的数据。
5. 新标签页只能由用户的直接点击触发，避免被浏览器拦截；打开时使用`noopener,noreferrer`。
6. 页面标题包含“对象名称 - 功能名称 - coreHR”，便于多个标签页并行辨识。
7. 浏览器刷新、复制链接和重新登录后，用户仍应回到同一受权资源；无权限时显示确定的拒绝结果，不能泄露对象是否存在。

## 5. Modal与Drawer规则

- Modal用于不离开当前任务即可完成的反馈或交互，遵循官方[Modal](https://ant.design/components/modal/)模式；创建和编辑表单可参考官方[Form](https://ant.design/components/form/)的Modal表单模式。
- Drawer用于仍需看见宿主页上下文的预览和编辑，遵循官方[Drawer](https://ant.design/components/drawer/)模式。
- 容器必须有明确标题、对象标识、主操作、次操作和关闭方式。危险操作不能把关闭按钮伪装成取消业务操作。
- 打开后焦点进入容器；关闭后焦点回到触发元素。键盘可以到达所有操作，焦点不得逃出Modal。
- 提交期间主操作进入加载状态并防止重复提交；失败时保留用户输入，错误落到对应字段或可感知的全局区域。
- 有未保存修改时，关闭按钮、Esc、遮罩关闭和宿主页面离开均执行同一离开确认策略。
- 明确表单生命周期：要求重新打开即为空时，关闭后销毁/重置表单；要求暂存时，必须有经批准的草稿机制，不能意外保留旧对象数据。
- 高风险操作说明具体对象、影响和是否可恢复，服务端仍须执行权限、并发和幂等校验。

## 6. 新浏览器标签页规则

- 适用于完整对象详情、多页签信息、长表单、历史版本、审计轨迹、跨对象比较、复杂流程和需要同时查看宿主页的任务。
- 每个标签页只有一个清晰主任务；详情信息按业务重要性建立层级，遵循官方[详情页原则](https://ant.design/docs/spec/detail-page/)。
- 新标签页不得自动再次打开更多标签页。需要跳转到另一个对象时，明确提供“在新标签页打开”动作。
- 保存成功后页面更新到服务端最新版本；关闭标签页由用户决定。不得通过脚本强制关闭非脚本创建或仍有未保存内容的标签页。
- 离开前提示仅在确有未保存变化时启用，避免正常浏览触发无意义确认。

## 7. 视觉、布局与组件规则

- 优先使用Ant Design原生组件、设计Token和语义结构；已有Token可以表达的颜色、间距、圆角、阴影和字号不得硬编码。
- 页面网格、间距和响应式遵循官方[布局规范](https://ant.design/docs/spec/layout/)，默认以8的倍数组织空间，但数据密集页面可在统一Token内采用紧凑模式。
- 表格具备加载、空数据、错误、分页、筛选结果为空和无权限状态；大数据使用服务端分页。
- 表单标签、帮助、必填、校验和错误恢复必须明确。高复杂度表单按任务顺序分组，不能简单堆叠字段。
- 状态不只依赖颜色，同时使用文字、图标或形状；交互元素有清晰焦点，文本与背景保持可读对比度。
- 通过`ConfigProvider`集中管理主题和本地化。需要上下文的Modal优先使用`App.useApp`或Hook方式，避免静态调用丢失主题、语言或权限上下文。

## 8. 功能需求必须提供的页面合同

每个涉及前端的功能需求必须明确：

1. 宿主页和触发入口。
2. 主载体：`MODAL`、`DRAWER`或`NEW_TAB`。
3. 载体选择理由，以及是否达到默认升级到新标签页的条件。
4. 页面标题、对象标识、主要操作、次要操作和退出结果。
5. 首次、加载、正常、空数据、部分失败、完全失败、无权限和数据冲突状态。
6. 表单校验、未保存变化、重复提交、成功反馈与下一步。
7. 键盘焦点、屏幕阅读器名称、响应式和敏感字段显示规则。
8. 稳定路由、权限校验、刷新恢复和多标签页并发修改策略。

## 9. Moka与Frappe参考图处理方式

收到外部系统截图后，按以下顺序转成coreHR输入：

1. 识别截图服务的用户、目标、业务对象和业务状态。
2. 拆解信息层级、入口、操作、字段分组、反馈和异常状态。
3. 分别记录“采用的业务规律”“为coreHR调整的部分”“明确不采用的部分”。
4. 把结果写入对应coreHR功能需求，分配功能、规则、权限和验收编号。
5. 基于本规范产出coreHR自己的页面结构和视觉方案，再进入开发。

截图不是已批准需求，也不是像素级复刻目标。不得复制对方代码、商标、图标资产、专有文案或具有明显识别性的整页视觉成品。

## 10. Pencil原型门禁

1. 每个新增或变更的前端页面必须在编码前建立Pencil原型；宿主页、Modal、Drawer和新标签页均属于页面范围。
2. 功能需求必须登记Pencil源文件、画板ID、画板名称、原型版本和Review状态。没有达到`PROTOTYPE_APPROVED`不得创建前端开发任务。
3. 原型至少表达页面框架、信息层级、主要操作、交互载体和关键状态。加载、空数据、失败、无权限或冲突状态存在显著视觉差异时，应以同画板状态区或独立状态画板表达。
4. 原型必须使用coreHR的Ant Design Token和信息架构；外部产品截图只能作为分析输入，不能直接转成可交付原型。
5. 产品决策人确认的是带版本的具体画板。原型变更影响已批准需求或代码时，必须先更新需求与原型版本，再按需求追踪注释规则修改代码。
6. Pencil原型是页面结构和交互Review证据，不替代业务规则、字段合同、权限、异常、接口、测试与可访问性验收。

## 11. 页面验收清单

- [ ] 页面遵循当前官方Ant Design稳定规范，且API兼容仓库锁定版本。
- [ ] 功能需求登记的Pencil画板已达到`PROTOTYPE_APPROVED`，实现与批准版本一致。
- [ ] 功能需求已经批准`MODAL`、`DRAWER`或`NEW_TAB`主载体。
- [ ] 宿主页未被当前标签页导航替换，筛选、分页、选中项和滚动上下文可以保留。
- [ ] 弹窗焦点、关闭、未保存变化、表单生命周期和重复提交行为通过测试。
- [ ] 新标签页有稳定URL、服务端权限校验、刷新恢复及`noopener,noreferrer`。
- [ ] 加载、空数据、错误、无权限、冲突和成功状态均有确定表现。
- [ ] 颜色、间距和排版使用Token，页面未私造Ant Design已有基础组件。
- [ ] 键盘、语义名称、焦点、对比度和敏感数据展示符合要求。
- [ ] 外部参考图已转成coreHR需求决策，没有直接复刻外部产品。
- [ ] 需求驱动的生产代码变化按规范写有稳定需求/决策ID的追踪注释。

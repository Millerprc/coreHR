# 企业输入包04：职务体系与职务目录

> 状态：`FIRST_ENTERPRISE_SAMPLE_CONFIRMED / CATALOG_EXPANDABLE`
> 输入顺序：第1项
> 数据安全：只含职务和配置代码，不填写人员姓名、工号或任职人员

## 1. 本轮目标

把企业正式的“职务→职级→职等→职类→序列”关系冻结为可导入、可生效日期管理的主数据。

通用能力已完成：

1. 职级、职等、职类、序列的独立配置和有效期版本。
2. 职务稳定代码对四个有效维度的版本化引用。
3. 职务维度和职务首版本及向前追加历史版本的 CSV 预校验、父级依赖排序及逐行拒绝报告。
4. 任职、编制、招聘需求和人事调动对目标日期有效职务的统一校验。
5. 管理端按日期查看、新建和新增版本，以及对应自动化测试。

2026-08-12已确认当前只有一个已知职务组合。项目采用推荐稳定代码冻结首版；后续新增目录时继续按本输入包追加，不等待完整目录才开展后续阶段。

## 2. 文件一：职务维度值

填写[01-job-dimensions.csv](./templates/01-job-dimensions.csv)。

| 字段 | 必填 | 说明 |
|---|---|---|
| `dimension_type` | 是 | `LEVEL/GRADE/CLASS/SEQUENCE`之一 |
| `dimension_code` | 是 | 稳定大写代码，创建后不随中文名修改 |
| `dimension_name` | 是 | 中文显示名称 |
| `parent_dimension_type` | 否 | 企业存在固定层级时填写父维度类型 |
| `parent_dimension_code` | 否 | 父维度稳定代码 |
| `sort_order` | 是 | 同类型显示顺序，整数 |
| `effective_from` | 是 | `YYYY-MM-DD` |
| `effective_to` | 否 | 空值表示长期有效 |
| `status` | 是 | `active/inactive` |
| `notes` | 否 | 特殊说明 |

如果“职级、职等、职类、序列”并非严格一对一层级，父维度两列可以留空；实际允许组合以职务目录为准。

## 3. 文件二：职务目录

填写[01-job-catalog.csv](./templates/01-job-catalog.csv)。每个职务一行。

| 字段 | 必填 | 说明 |
|---|---|---|
| `job_code` | 是 | 全局唯一稳定职务代码 |
| `job_name` | 是 | 正式职务名称 |
| `level_code` | 是 | 对应职级代码 |
| `grade_code` | 是 | 对应职等代码 |
| `class_code` | 是 | 对应职类代码 |
| `sequence_code` | 是 | 对应序列代码 |
| `effective_from` | 是 | `YYYY-MM-DD` |
| `effective_to` | 否 | 空值表示长期有效 |
| `status` | 是 | `active/inactive` |
| `source_job_id` | 否 | 如需保留来源ID则填写；新系统自建可留空 |
| `notes` | 否 | 同名职务区分、适用范围等说明 |

## 4. 当前已确认首批目录

当前唯一已知组合已经放入两份CSV：

```text
职务：劳动者产品部总经理
职级：6省总/专业总
职等：二级
职类：二级
序列：技术
```

本实验性新项目不依赖旧系统代码，因此采用 `LEVEL_06/GRADE_02/CLASS_02/TECH` 和 `JOB_LABOR_PRODUCT_GM` 作为首版稳定代码。以后中文名称变化时不改代码，只新增生效日期版本。

## 5. 可选：多段历史版本

同一稳定代码有多个生效日期版本时：

1. 最早一行仍分别填入[职务维度首版本](./templates/01-job-dimensions.csv)和[职务首版本](./templates/01-job-catalog.csv)。
2. 后续版本分别填入[职务维度历史版本](./templates/02-job-dimension-versions.csv)和[职务历史版本](./templates/02-job-catalog-versions.csv)。
3. 历史版本必须填写 `change_reason`；文件内可以乱序，系统按稳定代码、生效日期和父级依赖执行。
4. 在线导入只允许晚于数据库最新版本的日期向前追加，不允许倒插到已有版本之前。收到更早的遗留历史时，保留原始行并走本机离线迁移评审。

历史版本任务只用于导入，不提供“当前快照导出”入口，避免把当前快照误当成完整历史。

## 6. 验收闸门

- 同一维度代码不能重复表达不同含义。
- 相同中文名但含义不同的职务必须使用不同 `job_code`。
- 职务引用的四个维度代码必须存在且在职务生效日有效。
- 生效区间不得倒置；同一职务代码的版本不得重叠。
- 未知、空白、测试和停用维度不允许进入新任职或新编制。
- 旧EHR的 `JOB_GRADE/JOB_LEVEL/JOB_RANK/ZHINENG` 只作参考，不自动覆盖本输入包。
- 同一代码的首版本必须先建立；后续版本只能按日期向前追加。早于系统已有最新版本的遗留记录不可在线倒插，必须原样保留并单独评审迁移规则。
